Every `modal-computer-use` session revolves around a single question: **who owns the Sandbox?** The answer determines what happens when your context manager exits. When you *create* a Sandbox, the SDK owns it and will terminate it for you. When you *attach* to an existing one, the SDK merely borrows a connection and leaves the Sandbox running when it's done. Understanding this ownership model lets you write cleanup-safe code for both short-lived scripts and long-running desktop sessions.

## Lifecycle ownership at a glance

| Entry point | Who owns the Sandbox? | On context exit |
|---|---|---|
| `create()` | You (the caller) | Terminates, detaches, and closes the client |
| `attach()` | The original owner | Detaches and closes — Sandbox keeps running |
| `attach_or_create(name=...)` | You if it was just created; original owner if it already existed | Terminates if created; detaches if attached |
| `detach()` (called explicitly) | Transferred to caller-managed ownership | Does **not** terminate on context exit |
| `terminate()` | N/A — explicit stop | Immediately halts the Sandbox |

---

## `create()` — create and own a new Sandbox

Use `create()` when you want a fresh desktop that lives only as long as your `with` block. The SDK provisions a new Modal Sandbox, waits for daemon readiness, and terminates everything when the block ends.

<Tabs>
  <Tab title="Sync">
    ```python
    from modal_computer_use import ComputerConfig, ComputerSandbox

    config = ComputerConfig()

    with ComputerSandbox.create(config=config) as computer:
        computer.browser.open_url("https://example.com")
        screenshot = computer.screenshots.full()
        screenshot.save("result.png")
    # The Sandbox is terminated here automatically.
    ```
  </Tab>
  <Tab title="Async">
    ```python
    import asyncio
    from modal_computer_use import AsyncComputerSandbox, ComputerConfig

    config = ComputerConfig()

    async def main() -> None:
        async with AsyncComputerSandbox.create(config=config) as computer:
            await computer.browser.open_url("https://example.com")
            screenshot = await computer.screenshots.full()
            screenshot.save("result.png")
        # The Sandbox is terminated here automatically.

    asyncio.run(main())
    ```
  </Tab>
</Tabs>

### `wait` parameter

`create()` accepts a `wait` argument that controls how long the SDK waits before handing you the `computer` object:

- **`wait=True` (default)** — polls both Modal's sandbox readiness probe and the daemon `/readyz` endpoint. The `with` block only starts once the desktop is fully ready.
- **`wait=False`** — returns immediately after the connect token is created. The daemon may still be starting up. Use this only if you plan to call `computer.wait_until_ready()` manually later.

```python
# Return quickly; wait for readiness manually
with ComputerSandbox.create(config=config, wait=False) as computer:
    computer.wait_until_ready()
    computer.mouse.move(320, 240)
```

<Note>
`AsyncComputerSandbox` does not expose `wait=False`. Async contexts are always fully ready on entry.
</Note>

## `attach()` — connect to an existing Sandbox

Use `attach()` when a Sandbox is already running (created by another process, a previous script, or a colleague). Exiting the `with` block **closes your connection only** — the Sandbox keeps running.

`attach()` is non-blocking by default because you may only want to inspect metadata or call `terminate()`. Pass `wait=True` to poll `/readyz` before the block starts.

### Four attach paths

The SDK supports four mutually exclusive selectors:

<Tabs>
  <Tab title="By sandbox_id">
    ```python
    from modal_computer_use import ComputerSandbox

    with ComputerSandbox.attach(sandbox_id="sb-abc123") as computer:
        info = computer.display.info()
        print(info)
    # Connection closed; Sandbox still running.
    ```
  </Tab>
  <Tab title="By name">
    ```python
    from modal_computer_use import ComputerSandbox

    with ComputerSandbox.attach(
        name="support-desktop",
        app_name="modal-computer-use",
    ) as computer:
        screenshot = computer.screenshots.full()
        screenshot.save("support.png")
    # Connection closed; Sandbox still running.
    ```
  </Tab>
  <Tab title="By run_id">
    ```python
    from modal_computer_use import ComputerSandbox

    with ComputerSandbox.attach(run_id="support-ticket-123") as computer:
        result = computer.commands.run(["ls", "/home/desktop"])
        print(result.stdout)
    # Connection closed; Sandbox still running.
    ```
  </Tab>
  <Tab title="By base_url">
    ```python
    from modal_computer_use import ComputerSandbox

    # For directly reachable daemons — pass a token alongside the URL.
    with ComputerSandbox.attach(
        base_url="https://daemon.example",
        token="my-local-token",
    ) as computer:
        computer.mouse.click(100, 200)
    # Connection closed; daemon still running.
    ```
  </Tab>
</Tabs>

<Warning>
`token` is only valid with `base_url`. Modal-backed selectors (`sandbox_id`, `name`, `run_id`) resolve their authorization from the target Sandbox automatically.
</Warning>

### Async attach

```python
import asyncio
from modal_computer_use import AsyncComputerSandbox

async def inspect() -> None:
    async with AsyncComputerSandbox.attach(sandbox_id="sb-abc123") as computer:
        metadata = await computer.session.metadata()
        print(metadata)

asyncio.run(inspect())
```

Async attachment accepts exactly one Modal selector (`sandbox_id`, `name`, or `run_id`). Direct daemon URLs go through `AsyncDaemonClient` instead.

## `attach_or_create(name=...)` — acquire or create a named Sandbox

Use this pattern when you want exactly one live Sandbox with a given name. If no Sandbox with that name exists, the SDK creates one. If one already exists, the SDK attaches to it. Ownership — and therefore what happens on exit — follows which branch ran:

<Tabs>
  <Tab title="Sync">
    ```python
    from modal_computer_use import ComputerConfig, ComputerSandbox

    config = ComputerConfig()

    with ComputerSandbox.attach_or_create(
        name="support-desktop",
        config=config,
    ) as computer:
        computer.browser.open_url("https://internal-tool.example.com")
        screenshot = computer.screenshots.full()
    # If the SDK created this Sandbox, it is terminated here.
    # If the SDK attached to an existing Sandbox, it keeps running.
    ```
  </Tab>
  <Tab title="Async">
    ```python
    import asyncio
    from modal_computer_use import AsyncComputerSandbox, ComputerConfig

    config = ComputerConfig()

    async def main() -> None:
        async with AsyncComputerSandbox.attach_or_create(
            name="support-desktop",
            config=config,
        ) as computer:
            await computer.browser.open_url("https://internal-tool.example.com")
            screenshot = await computer.screenshots.full()

    asyncio.run(main())
    ```
  </Tab>
</Tabs>

`attach_or_create()` defaults to `wait=True` for both the creation and attachment branches, so the `computer` object is always ready when your block starts.

<Note>
The `name` is Modal's app-scoped live allocation key. If two callers race to create a Sandbox with the same name, the SDK handles the `AlreadyExistsError` from Modal with a bounded lookup of the winner — you don't need to worry about that race in your code.
</Note>

## `detach()` — transfer ownership to the caller

If you create a Sandbox inside a `with` block but want to keep it running after the block ends, call `detach()` before exiting. This transfers lifecycle ownership from the SDK's context manager to your own code, preventing the automatic termination that would otherwise happen.

<Tabs>
  <Tab title="Sync">
    ```python
    from modal_computer_use import ComputerConfig, ComputerSandbox

    config = ComputerConfig()

    with ComputerSandbox.create(config=config) as computer:
        computer.browser.open_url("https://example.com")
        sandbox_id = computer.metadata().sandbox_id

        # Hand off ownership — the context manager will no longer terminate.
        computer.detach()

    # The Sandbox is still running. You are responsible for terminating it later.
    print(f"Sandbox {sandbox_id} is still running — terminate it when done.")

    # Later, in another script or function:
    with ComputerSandbox.attach(sandbox_id=sandbox_id) as computer:
        computer.terminate()
    ```
  </Tab>
  <Tab title="Async">
    ```python
    import asyncio
    from modal_computer_use import AsyncComputerSandbox, ComputerConfig

    config = ComputerConfig()

    async def main() -> None:
        async with AsyncComputerSandbox.create(config=config) as computer:
            await computer.browser.open_url("https://example.com")
            await computer.detach()
            # Context exit no longer terminates the Sandbox.

    asyncio.run(main())
    ```
  </Tab>
</Tabs>

<Warning>
After calling `detach()`, **you** are responsible for calling `terminate()` when the Sandbox is no longer needed. Forgetting to do so will leave the Sandbox running and consuming Modal credits until its `runtime.timeout_seconds` expires.
</Warning>

## `terminate()` — explicit stop

Call `terminate()` to stop a Sandbox immediately, regardless of who owns it or whether you're inside a `with` block.

```python
from modal_computer_use import ComputerSandbox

# Attach without taking ownership, then explicitly stop.
with ComputerSandbox.attach(sandbox_id="sb-abc123") as computer:
    computer.terminate()
```

You can also terminate outside a `with` block using the `ComputerSandboxManager`:

```python
from modal_computer_use import ComputerSandboxManager

manager = ComputerSandboxManager()
manager.terminate(sandbox_id="sb-abc123")
```

## Lifecycle summary

<Steps>
  <Step title="Provision">
    Call `create()` (or `attach_or_create()`) to start a Sandbox. The SDK waits for Modal and daemon readiness before entering your block.
  </Step>
  <Step title="Use">
    Drive the desktop through `computer.*` namespaces — mouse, keyboard, browser, screenshots, and more.
  </Step>
  <Step title="Hand off (optional)">
    Call `detach()` if you want the Sandbox to outlive your current context. Record the `sandbox_id` so you can reconnect later.
  </Step>
  <Step title="Terminate">
    The context manager terminates the Sandbox automatically (for `create()`) when your block ends. For detached or attached Sandboxes, call `terminate()` explicitly when the work is complete.
  </Step>
</Steps>
