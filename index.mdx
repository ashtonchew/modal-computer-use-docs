Modal Computer Use provides a typed Python SDK and an in-Sandbox daemon. Your application owns the
model loop. The SDK owns Modal orchestration. The daemon executes desktop primitives inside the
Sandbox.

This is an independent project that uses Modal.

## Use the primary path

The 2.x path has one owner and one borrower:

1. An async owner creates the desktop once.
2. The owner creates a versioned session handle.
3. The owner sends the handle to an explicitly placed Modal Function.
4. The Function enters one `borrow_async()` context for the trajectory.
5. Each model action array uses one `computer.step()` call.
6. The borrower releases its lease before the owner cleans up the desktop.

`computer.step()` validates and runs one ordered action array. It returns the action result and one
immediate post-action screenshot. Your application defines readiness and task success.

## Choose the right surface

| Need | Interface |
| --- | --- |
| Repeated model turns | One placed Function, one borrow, and `computer.step()` |
| Initial or screenshot-only observation | `computer.screenshots.full()` |
| Local daemon work | `DaemonClient.local()` or `AsyncDaemonClient.local()` |
| Direct REST or debugging | The retained daemon routes and OpenAPI schema |
| Compatibility without handoff | Explicit low-level create, attach, and direct-client paths |

Low-level paths remain supported for callers that establish and own their topology explicitly.

## Understand the latency evidence

The article's 47.10 ms value adds separate 37.25 ms screenshot and 9.85 ms click medians. A later
fixed-topology benchmark measured the fused `computer.step()` path at 44.29 ms p50 and 52.57 ms
p95. Read the [current benchmark results](/benchmarks/current-results) for both measurement scopes
and source revisions.
