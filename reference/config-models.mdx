`ComputerConfig` is the single entry point for configuring a modal-computer-use desktop. You pass it to `ComputerSandbox.create()` or `AsyncComputerSandbox.create()`, and the SDK maps each field to the correct Modal orchestration argument or daemon environment variable. All nested models reject unknown keys, so typos fail at construction time rather than silently applying wrong defaults. Nested models can be supplied either as model instances or as plain Python dictionaries.

<Note>
`ComputerConfig` does not read environment variables or a config file. Pydantic defaults apply first; values you pass replace those defaults. To configure the daemon process directly (for custom deployments without the SDK), see the [Environment Variables reference](/reference/environment-variables).
</Note>

---

## DesktopConfig

Controls the virtual display geometry and desktop compositor.

<ParamField path="desktop.resolution" type="tuple[int, int]" default="(1024, 768)">
  Display size as `(width, height)` in pixels. Width must be at least `320` and height at least `240`. Total pixel count must not exceed `8,294,400` (roughly 4 K). Maps to `COMPUTER_USE_DESKTOP_WIDTH` and `COMPUTER_USE_DESKTOP_HEIGHT`.
</ParamField>

<ParamField path="desktop.dpi" type="int" default="96">
  Dots-per-inch for the virtual display. Accepted range: `48` to `240`. Maps to `COMPUTER_USE_DESKTOP_DPI`.
</ParamField>

<ParamField path="desktop.window_manager" type='"xfce" | "openbox"' default='"xfce"'>
  Desktop window manager to launch. Named images always require `"xfce"`. Maps to `COMPUTER_USE_WINDOW_MANAGER`.
</ParamField>

<ParamField path="desktop.display_depth" type="int" default="24">
  Color depth for the X display, in bits. Accepted range: `8` to `32`. Maps to `COMPUTER_USE_DISPLAY_DEPTH`.
</ParamField>

```python
from modal_computer_use import ComputerConfig

config = ComputerConfig(
    desktop={"resolution": (1920, 1080), "dpi": 120, "window_manager": "xfce"}
)
```

## RuntimeConfig

Controls Modal orchestration timeouts and placement. These fields configure the Modal sandbox itself and are **not** daemon environment variables (except for budget fields described under `BudgetConfig`).

<ParamField path="runtime.timeout_seconds" type="int" default="3600">
  Maximum lifetime of the Modal Sandbox in seconds. Range: `1` to `86400` (24 hours). Passed directly to Modal as the Sandbox lifetime timeout.
</ParamField>

<ParamField path="runtime.idle_timeout_seconds" type="int | None" default="None">
  Modal Sandbox idle timeout in seconds. Range: `1` to `86400` when set; `None` means no idle limit. Warm capacity does not support an explicit value.
</ParamField>

<ParamField path="runtime.readiness_timeout_seconds" type="int" default="120">
  How long the SDK waits for both Modal's sandbox readiness probe and the daemon `/readyz` endpoint before giving up. Range: `1` to `900`. This is an SDK-side deadline and does not map to `COMPUTER_USE_READINESS_CACHE_TTL_MS`.
</ParamField>

<ParamField path="runtime.modal_environment" type="str | None" default="None">
  Non-empty Modal environment name to use for `App.lookup`. When set, it selects the environment for Modal API calls. Independent of `image.environment_name`, which selects a published named image.
</ParamField>

<ParamField path="runtime.modal_region" type="str | None" default="None">
  Non-empty Modal region string requesting where the Sandbox should be placed. Passed through to Modal as a placement hint.
</ParamField>

## ResourceConfig

Sets the compute profile and hardware resources for the Sandbox. `cpu` and `memory_mib` are requests, not caps—Modal charges whichever is higher, the request or actual usage.

<ParamField path="resources.profile" type='"standard" | "browser" | "browser-gpu" | "custom"' default='"standard"'>
  Managed image recipe to select. `"standard"` is a general-purpose desktop; `"browser"` and `"browser-gpu"` add browser-optimized tuning; `"custom"` bypasses recipe selection. Named images do not support `"custom"`. Maps to the informational `COMPUTER_USE_IMAGE_PROFILE`.
</ParamField>

<ParamField path="resources.cpu" type="float | None" default="provider default">
  CPU cores to request. Must be a positive number when set. Modal counts physical cores, not vCPU, with a per-container floor of `0.125`. Passed to Modal as `cpu`.
</ParamField>

<ParamField path="resources.memory_mib" type="int | None" default="provider default">
  Memory to request in mebibytes. Minimum `128` when set. The alias `memory_mb` is also accepted as an input. Passed to Modal as `memory`.
</ParamField>

<ParamField path="resources.gpu" type="str | None" default="provider default">
  Modal GPU request string (for example `"T4"` or `"A10G"`). Passed through to Modal unchanged.
</ParamField>

## ImageConfig

Controls which container image the SDK selects for the Sandbox.

<ParamField path="image.source" type='"inline" | "named"' default='"inline"'>
  `"inline"` builds or selects an SDK-managed recipe image based on `resources.profile`. `"named"` selects a published, revision-tagged image by its Git SHA. Passing an explicit `image=` to `ComputerSandbox.create()` bypasses this step entirely.
</ParamField>

<ParamField path="image.revision" type="str | None" default="None">
  For `source="named"`: the required full 40-character lowercase hexadecimal Git SHA of the published image. Invalid for inline images.
</ParamField>

<ParamField path="image.environment_name" type="str | None" default="None">
  Optional Modal environment for named-image and app lookup. Non-empty when set. Invalid for inline images. Independent of `runtime.modal_environment`.
</ParamField>

<Warning>
Named images require `desktop.window_manager="xfce"` and do not support `resources.profile="custom"`. If you use the `"browser"` or `"browser-gpu"` profile with a named image, you must also set `browser.kind` and `browser.prewarm=True`.
</Warning>

## NetworkConfig

Manages outbound network policy, ingress transport, and allowlists for the Sandbox.

<ParamField path="network.block_all" type="bool" default="false">
  Block all network access for the Sandbox. Passed to Modal as `block_network`. Cannot be combined with any allowlist. Requires `ingress="connect"` and VNC disabled (`expose_vnc="off"`). The alias `blocked` is also accepted.
</ParamField>

<ParamField path="network.daemon_http_version" type='"1.1" | "2"' default='"1.1"'>
  HTTP version used by the SDK to communicate with the daemon. `"2"` uses cleartext HTTP/2 (`h2c`) inside the Sandbox. Maps to `COMPUTER_USE_DAEMON_HTTP_VERSION`.
</ParamField>

<ParamField path="network.outbound_cidr_allowlist" type="list[str] | None" default="None">
  List of CIDR ranges to permit for outbound traffic. Each entry must be a valid, non-empty CIDR string. Passed to Modal. Compatibility aliases: `cidr_allowlist`, `allowlist`. The `cidr_allowlist` property name is deprecated.
</ParamField>

<ParamField path="network.outbound_domain_allowlist" type="list[str] | None" default="None">
  List of domain names to permit for outbound traffic. Each entry must be non-empty. Passed to Modal.
</ParamField>

<ParamField path="network.inbound_cidr_allowlist" type="list[str] | None" default="None">
  List of CIDR ranges permitted for inbound connections. Each entry must be a valid, non-empty CIDR string. Passed to Modal.
</ParamField>

<ParamField path="ingress" type='"attested-tunnel" | "connect" | "tunnel"' default='"attested-tunnel"'>
  Transport used by the SDK to reach the daemon. `"attested-tunnel"` mints a short-lived session token from an SDK-managed bootstrap bearer. `"connect"` stays on Modal Connect and requires the verified-user header. `"tunnel"` uses the bootstrap bearer directly without attestation. Defined at the top level of `ComputerConfig`, not inside `NetworkConfig`.
</ParamField>

## StorageConfig

Configures paths for artifacts, recordings, and action traces inside the Sandbox.

<ParamField path="storage.recordings_dir" type="str" default='"/home/desktop/recordings"'>
  Daemon-internal path where screen recordings are written. Maps to `COMPUTER_USE_RECORDINGS_DIR`. The alias `recording_dir` is also accepted.
</ParamField>

<ParamField path="storage.artifacts_dir" type="str" default='"/home/desktop/artifacts"'>
  Root path for the artifact store inside the Sandbox. Maps to `COMPUTER_USE_ARTIFACTS_DIR`.
</ParamField>

<ParamField path="storage.persist_artifacts" type="bool" default="false">
  Declare that artifacts should be persisted to a Modal Volume. When `true`, a Modal Volume must be mounted at `artifacts_dir` or one of its parents at creation time. Maps to `COMPUTER_USE_ARTIFACTS_PERSISTENT`. The SDK separately computes the `COMPUTER_USE_ARTIFACTS_VOLUME_MOUNTED` proof flag; you do not set it directly.
</ParamField>

<ParamField path="storage.trace_dir" type="str" default='"/home/desktop/artifacts/traces"'>
  Directory inside the Sandbox where NDJSON action traces are written when tracing is enabled. Maps to `COMPUTER_USE_TRACE_DIR`.
</ParamField>

## BrowserConfig

Configures the browser that is launched inside the Sandbox. When you omit `browser` entirely (the default `None`), the SDK does not select or prewarm any browser. Supply a `BrowserConfig` instance or dictionary to opt in.

<ParamField path="browser.kind" type='"firefox" | "chromium" | None' default="None">
  Browser to use. When unset, the daemon falls back to `xdg-open` for generic URL opening. Maps to `COMPUTER_USE_BROWSER`.
</ParamField>

<ParamField path="browser.prewarm" type="bool" default="true">
  Launch the selected browser at daemon startup. When no `browser` object is supplied, the SDK sends `false`. Maps to `COMPUTER_USE_BROWSER_PREWARM`.
</ParamField>

<ParamField path="browser.profile_dir" type="str | None" default="None">
  Browser profile directory path inside the Sandbox. When unset, the daemon resolves it to `/home/desktop/.cache/modal-computer-use/browser-profile` at use time. Maps to `COMPUTER_USE_BROWSER_PROFILE_DIR`.
</ParamField>

<ParamField path="browser.launch_args" type="list[str]" default="[]">
  Additional command-line arguments passed to the browser at launch. No entry may contain a NUL byte. Encoded as a JSON array in `COMPUTER_USE_BROWSER_LAUNCH_ARGS`.
</ParamField>

<ParamField path="browser.open_url_on_start" type="str | None" default="None">
  URL to open when the browser first starts. Takes precedence over blank-page prewarm. Treat this value as secret-bearing. Maps to `COMPUTER_USE_BROWSER_OPEN_URL_ON_START`.
</ParamField>

<ParamField path="browser.gpu_mode" type='"auto" | "off" | "chromium-vulkan" | None' default="None">
  GPU acceleration mode for the browser. `None` is resolved to `"auto"` by the SDK. Maps to `COMPUTER_USE_BROWSER_GPU_MODE`.
</ParamField>

## ActionConfig

Governs action batching, timeouts, input rate limits, and subprocess execution within the Sandbox daemon.

<ParamField path="actions.post_action_delay_ms" type="int" default="0">
  Milliseconds to pause after each UI-mutating action before the next action or `screenshot_after` capture. Range: `0` to `10000`. Maps to `COMPUTER_USE_POST_ACTION_DELAY_MS`.
</ParamField>

<ParamField path="actions.screenshot_after" type="bool" default="false">
  Retained SDK configuration field. Not projected to the daemon environment and is not a global default for `actions.run`. Use the per-call `screenshot_after=` argument instead.
</ParamField>

<ParamField path="actions.trace_actions" type="bool" default="false">
  Append a trace entry to the trace directory for every executed action. Maps to `COMPUTER_USE_TRACE_ACTIONS`. The alias `action_trace` is also accepted.
</ParamField>

<ParamField path="actions.screenshot_processing_location" type='"auto" | "daemon" | "client"' default='"auto"'>
  Hint for where screenshot processing occurs. The daemon records this but currently no route branches on it. Maps to `COMPUTER_USE_SCREENSHOT_PROCESSING_LOCATION`. The alias `screenshot_processing` is also accepted.
</ParamField>

<ParamField path="actions.max_batch_actions" type="int" default="50">
  Maximum number of actions allowed in a single `/v1/actions/run` batch, including nested actions. Range: `1` to `500`. Maps to `COMPUTER_USE_MAX_BATCH_ACTIONS`.
</ParamField>

<ParamField path="actions.max_batch_duration_ms" type="int" default="30000">
  Wall-clock deadline in milliseconds for an entire action batch, including nested execution. The batch stops when this deadline is reached even if `continue_on_error=true`. Range: `1` to `600000`. Maps to `COMPUTER_USE_MAX_BATCH_DURATION_MS`.
</ParamField>

<ParamField path="actions.default_action_timeout_ms" type="int" default="5000">
  Per-action timeout in milliseconds used when neither the action nor the request supplies an explicit timeout. Range: `1` to `300000`. Must not exceed `max_action_timeout_ms`. Maps to `COMPUTER_USE_DEFAULT_ACTION_TIMEOUT_MS`.
</ParamField>

<ParamField path="actions.max_action_timeout_ms" type="int" default="300000">
  Upper bound on any per-action or per-request timeout. Requests supplying a larger value are rejected. Range: `1` to `600000`. Maps to `COMPUTER_USE_MAX_ACTION_TIMEOUT_MS`.
</ParamField>

<ParamField path="actions.input_rate_limit_per_sec" type="int" default="20">
  Rolling one-second cap on input-affecting actions across all mutation routes. `0` disables the limit. Range: `0` to `10000`. Maps to `COMPUTER_USE_INPUT_RATE_LIMIT_PER_SEC`.
</ParamField>

<ParamField path="actions.input_backend" type='"auto" | "xtest" | "xdotool"' default='"auto"'>
  Input adapter policy. `"auto"` prefers the persistent XTest/XKB path and falls back to compatibility only before emission. `"xtest"` forces native XTest/XKB. `"xdotool"` forces the legacy `xdotool` adapter. Maps to `COMPUTER_USE_INPUT_BACKEND`.
</ParamField>

<ParamField path="actions.subprocess_backend" type='"asyncio" | "threaded" | "isolated-asyncio"' default='"isolated-asyncio"'>
  Backend used for subprocess-backed command and compatibility execution (not native XTest input). Maps to `COMPUTER_USE_SUBPROCESS_BACKEND`.
</ParamField>

## BudgetConfig

Enforces per-session consumption limits. All budget fields are unset (unlimited) by default; each value you set must be a positive integer of at least `1`.

<ParamField path="budgets.max_actions" type="int | None" default="None">
  Maximum number of attempted executable desktop actions per session. Failed and timed-out attempts count; validation failures, idempotency replays, screenshots, zooms, and cursor queries do not. Maps to `COMPUTER_USE_MAX_ACTIONS`.
</ParamField>

<ParamField path="budgets.max_screenshots" type="int | None" default="None">
  Maximum number of reserved screenshot operations per session. Maps to `COMPUTER_USE_MAX_SCREENSHOTS`.
</ParamField>

<ParamField path="budgets.max_artifact_bytes" type="int | None" default="None">
  Maximum projected bytes allowed in the artifact store, accounting for replacement of an existing artifact. Maps to `COMPUTER_USE_MAX_ARTIFACT_BYTES`.
</ParamField>

<ParamField path="budgets.max_recording_seconds" type="int | None" default="None">
  Maximum total recording duration in seconds across all recordings in the session. Maps to `COMPUTER_USE_MAX_RECORDING_SECONDS`.
</ParamField>

<ParamField path="budgets.max_idle_seconds" type="int | None" default="None">
  Maximum number of seconds since the last budget-counted activity before the daemon enforces a stop. This is enforced by the daemon and is distinct from Modal's `runtime.idle_timeout_seconds`. Maps to `COMPUTER_USE_MAX_IDLE_SECONDS`.
</ParamField>

## Top-level ComputerConfig fields

These fields live directly on `ComputerConfig` alongside the nested sub-models above.

<ParamField path="run_id" type="str | None" default="generated at creation">
  Optional session correlation identifier. Mapped to `COMPUTER_USE_RUN_ID` and Modal's Sandbox lifecycle tags. Use this to correlate logs, traces, and artifacts across your infrastructure.
</ParamField>

<ParamField path="expose_vnc" type='"off" | "view_only" | "control" | bool' default='"off"'>
  noVNC exposure mode. `"off"` disables VNC. `"view_only"` allows watching without input. `"control"` enables full interaction. Compatibility booleans: `False` maps to `"off"`, `True` maps to `"control"`. Maps to `COMPUTER_USE_VNC_MODE` and Modal port `6080` exposure.
</ParamField>

<ParamField path="vnc_password" type="str | None" default="generated when needed">
  Password protecting the noVNC endpoint. When VNC is enabled and this is unset, the SDK generates a password automatically. Excluded from model serialization, `repr()` output, configuration hashes, and tags. Treat as secret. Warm capacity does not accept an explicit password.
</ParamField>

## Complete assembled example

```python
from modal_computer_use import ComputerConfig

config = ComputerConfig(
    desktop={
        "resolution": (1280, 800),
        "dpi": 96,
        "window_manager": "xfce",
        "display_depth": 24,
    },
    runtime={
        "timeout_seconds": 1800,
        "idle_timeout_seconds": 300,
        "readiness_timeout_seconds": 120,
        "modal_region": "us-east",
    },
    resources={
        "profile": "browser",
        "cpu": 2.0,
        "memory_mib": 4096,
    },
    image={
        "source": "inline",
    },
    network={
        "daemon_http_version": "1.1",
        "outbound_domain_allowlist": ["example.com", "api.example.com"],
    },
    storage={
        "artifacts_dir": "/home/desktop/artifacts",
        "persist_artifacts": False,
        "trace_dir": "/home/desktop/artifacts/traces",
    },
    browser={
        "kind": "chromium",
        "prewarm": True,
        "launch_args": ["--no-sandbox"],
        "gpu_mode": "auto",
    },
    actions={
        "post_action_delay_ms": 100,
        "max_batch_actions": 50,
        "default_action_timeout_ms": 5000,
        "input_backend": "auto",
    },
    budgets={
        "max_actions": 1000,
        "max_screenshots": 500,
        "max_artifact_bytes": 104857600,  # 100 MiB
    },
    run_id="my-task-run-001",
    expose_vnc="off",
    ingress="attested-tunnel",
)
```
