`modal-computer-use` returns strongly-typed Pydantic models from every SDK operation. All public models are exported directly from the top-level `modal_computer_use` package, so you can import them alongside the client classes you already use. This page documents every return type grouped by the area of the SDK that produces it — screenshots, actions, sessions, artifacts, sandbox management, and warm-pool capacity.

```python
from modal_computer_use import (
    Screenshot, ScreenshotOptions, DisplayInfo, DisplayGeometry,
    Region, Point, CoordinateSpace,
    ActionBatchResult, ActionBatchTiming, ActionItemResult, ActionResult,
    ActionDecision, ComputerAction, ActionObservationResult,
    ComputerStatus, ComputerSessionHandle, SandboxRef, DebugUrls,
    SessionRecoveryStatus, SessionRecoveryAcknowledgement,
    ArtifactInfo, ArtifactSyncResult, Recording, X11Window, ProcessStatus,
    SandboxCleanupItem, SandboxCleanupResult, SessionStartupTiming,
    WarmPoolPolicy, WarmPoolEntry, WarmPoolClaim, WarmPoolClaimMetrics,
    WarmPoolFillResult, WarmPoolReconcileResult,
)
```

## Screenshots and display

### `Screenshot`

The primary return type for all screenshot operations (`computer.screenshots.full()`, `.region()`, `.zoom()`). A `Screenshot` always carries its dimensions, format, and at least one of: raw bytes, a base64 payload, or an artifact URI.

<ResponseField name="format" type='"png" | "jpeg" | "webp"' required>
  Image format of the captured screenshot.
</ResponseField>

<ResponseField name="width" type="int" required>
  Width of the image in pixels. Always greater than zero.
</ResponseField>

<ResponseField name="height" type="int" required>
  Height of the image in pixels. Always greater than zero.
</ResponseField>

<ResponseField name="size_bytes" type="int" required>
  Byte length of the encoded image payload. Zero when the image is artifact-backed and not yet downloaded.
</ResponseField>

<ResponseField name="bytes" type="bytes | None">
  Raw image bytes when the screenshot was captured with `storage="inline"`. `None` for artifact-backed screenshots.
</ResponseField>

<ResponseField name="data_base64" type="str | None">
  Base64-encoded image string, available when the daemon returned the image inline in a JSON response.
</ResponseField>

<ResponseField name="artifact_uri" type="str | None">
  Artifact URI for screenshots stored with `storage="artifact"` or `storage="auto"`. Use `computer.artifacts.read_bytes(path)` to download.
</ResponseField>

<ResponseField name="sha256" type="str | None">
  Hex SHA-256 digest of the image bytes, when provided by the daemon.
</ResponseField>

<ResponseField name="captured_at" type="datetime">
  UTC timestamp when the screenshot was taken.
</ResponseField>

<ResponseField name="coordinate_space" type="CoordinateSpace" required>
  Mapping between desktop coordinates and image coordinates. Use this when passing the screenshot to an AI provider adapter.
</ResponseField>

<ResponseField name="cursor_visible" type="bool">
  Whether the cursor was visible at capture time. Always `False` unless you passed `show_cursor=True` to the screenshot options.
</ResponseField>

<ResponseField name="cursor_position" type="Point | None">
  Cursor position in desktop coordinates at capture time, if available.
</ResponseField>

**Helper methods:**

```python
screenshot = await computer.screenshots.full()

# Get raw bytes regardless of storage mode (raises if artifact-backed)
raw: bytes = screenshot.as_bytes()

# Get base64 string regardless of storage mode
b64: str = screenshot.to_base64()

# Save to disk and get the resolved Path back
path = screenshot.save("/tmp/frame.png")

# Convert to a PIL Image (requires Pillow)
img = screenshot.to_pil()
```

<Warning>
Calling `as_bytes()` on an artifact-backed screenshot (where `bytes` and `data_base64` are both `None`) raises `ValueError`. Download the artifact first with `computer.artifacts.read_bytes()`, or use `storage="inline"` in `ScreenshotOptions`.
</Warning>

### `ScreenshotOptions`

Controls how the daemon captures and encodes screenshots. Pass an instance to any screenshot operation via the `options` parameter.

<ResponseField name="format" type='"png" | "jpeg" | "webp"'>
  Image encoding format. Defaults to `"png"`.
</ResponseField>

<ResponseField name="quality" type="int">
  Compression quality from 1 to 100 (inclusive). Applies to JPEG and WebP. Defaults to `90`.
</ResponseField>

<ResponseField name="scale" type="float">
  Downscale factor relative to native resolution. Values in `(0, 8]`. Defaults to `1.0` (no scaling).
</ResponseField>

<ResponseField name="show_cursor" type="bool">
  Include the hardware cursor in the captured image. Defaults to `False`.
</ResponseField>

<ResponseField name="storage" type='"inline" | "artifact" | "auto"'>
  Where the image payload is placed. `"inline"` returns bytes in the response body; `"artifact"` writes to the artifact store and returns a URI; `"auto"` lets the daemon choose based on image size. Defaults to `"inline"`.
</ResponseField>

<ResponseField name="processing" type='"daemon" | "client" | "auto"'>
  Whether image encoding happens on the daemon or is streamed raw to the client. Defaults to `"auto"`.
</ResponseField>

### `Region`

An axis-aligned rectangular region in desktop pixel coordinates. Used as an input to `computer.screenshots.region()`, `computer.screenshots.zoom()`, and `CoordinateSpace`.

<ResponseField name="x" type="int" required>
  Left edge. Must be ≥ 0.
</ResponseField>

<ResponseField name="y" type="int" required>
  Top edge. Must be ≥ 0.
</ResponseField>

<ResponseField name="width" type="int" required>
  Width. Must be > 0.
</ResponseField>

<ResponseField name="height" type="int" required>
  Height. Must be > 0.
</ResponseField>

**Computed properties:** `.right` returns `x + width`; `.bottom` returns `y + height`.

<ResponseField name="y" type="int" required>

### `CoordinateSpace`

Describes the mapping between desktop coordinates and screenshot image coordinates. This model is attached to every `Screenshot` and used by AI provider adapters to translate model-returned pixel coordinates back to desktop space before issuing actions.

<ResponseField name="desktop_width" type="int" required>
  Full desktop width in pixels.
</ResponseField>

<ResponseField name="desktop_height" type="int" required>
  Full desktop height in pixels.
</ResponseField>

<ResponseField name="image_width" type="int" required>
  Width of the captured image in pixels (may differ from `desktop_width` when scaled or region-cropped).
</ResponseField>

<ResponseField name="image_height" type="int" required>
  Height of the captured image in pixels.
</ResponseField>

<ResponseField name="scale_x" type="float">
  Horizontal scale factor (`image_width / source_width`). Defaults to `1.0`.
</ResponseField>

<ResponseField name="scale_y" type="float">
  Vertical scale factor (`image_height / source_height`). Defaults to `1.0`.
</ResponseField>

<ResponseField name="source_region" type="Region | None">
  When the screenshot was taken with `computer.screenshots.region()` or `zoom()`, this is the captured subregion within the desktop. `None` for full-screen captures.
</ResponseField>

**Coordinate translation methods:**

```python
# Translate a point from image space to desktop space
desktop_pt: Point = space.to_desktop(Point(x=320, y=240))

# Translate a point from desktop space to image space
image_pt: Point = space.to_image(Point(x=640, y=480))
```

Provider adapters call `to_desktop()` automatically when an explicit `CoordinateSpace` is configured. You only need to call these methods directly if you are writing a custom adapter.

## Actions and results

### `ActionBatchResult`

Returned by `computer.actions.run()` and `computer.actions.apply()`. Contains the outcome of every action in the batch plus an optional trailing screenshot.

<ResponseField name="ok" type="bool" required>
  `True` when all actions in the batch succeeded. `False` if any action failed (even when `continue_on_error=True` was used).
</ResponseField>

<ResponseField name="call_id" type="str | None">
  Opaque call identifier echoed from the request, if one was supplied.
</ResponseField>

<ResponseField name="results" type="list[ActionItemResult]" required>
  Per-action outcomes, one entry per action in the original batch. The list preserves the original order.
</ResponseField>

<ResponseField name="screenshot" type="Screenshot | None">
  Trailing screenshot captured after all batch actions completed, when `screenshot_after=True` was set on the request.
</ResponseField>

<ResponseField name="timing" type="ActionBatchTiming | None">
  Elapsed-time metadata measured inside the daemon.
</ResponseField>

---

### `ActionBatchTiming`

Timing metadata attached to every successful `ActionBatchResult`.

<ResponseField name="daemon_ms" type="float" required>
  Elapsed milliseconds measured entirely inside the daemon for the batch request. This excludes network round-trip time and client-side serialization.
</ResponseField>

<Note>
`ActionBatchTiming` contains only elapsed milliseconds. It never contains command strings, typed text, clipboard contents, screenshots, or paths.
</Note>

---

### `ActionItemResult`

The per-action outcome within an `ActionBatchResult`.

<ResponseField name="index" type="int" required>
  Zero-based position of this action in the original batch.
</ResponseField>

<ResponseField name="type" type="str" required>
  The action type string (e.g. `"click"`, `"type"`, `"screenshot"`).
</ResponseField>

<ResponseField name="ok" type="bool" required>
  Whether this action succeeded.
</ResponseField>

<ResponseField name="elapsed_ms" type="float | None">
  Time taken to execute this individual action, in milliseconds. `None` when not measured.
</ResponseField>

<ResponseField name="error_code" type="str | None">
  Machine-readable error code when `ok=False`. Common values include `"timeout"`, `"input_backend_unavailable"`, `"input_may_be_partial"`, and `"input_state_conflict"`.
</ResponseField>

<ResponseField name="error" type="str | None">
  Human-readable error message when `ok=False`.
</ResponseField>

<ResponseField name="output" type="dict[str, Any]">
  Action-specific output payload. For screenshot actions, contains the screenshot data. For errors, contains structured `{code, ...details}` fields.
</ResponseField>

---

### `ActionResult`

A general-purpose result returned by simple action endpoints (not action batch endpoints).

<ResponseField name="ok" type="bool">
  Whether the operation succeeded. Defaults to `True`.
</ResponseField>

<ResponseField name="message" type="str | None">
  Optional human-readable message.
</ResponseField>

<ResponseField name="elapsed_ms" type="float | None">
  Time taken, in milliseconds.
</ResponseField>

<ResponseField name="output" type="dict[str, Any]">
  Action-specific output payload.
</ResponseField>

---

### `ActionDecision`

Returned by policy hooks attached to provider adapters. A hook receives the normalized `ComputerAction` before it is sent to the daemon and returns an `ActionDecision` to allow or block it.

<ResponseField name="decision" type='"allow" | "deny" | "ask_user" | "handoff"' required>
  The policy outcome. Only `"allow"` permits the action to proceed. Any other value causes the executor to raise before sending the batch.
</ResponseField>

<ResponseField name="reason" type="str | None">
  Optional explanation for the decision, used for logging and debugging.
</ResponseField>

```python
from modal_computer_use import ActionDecision

def my_policy_hook(action) -> ActionDecision:
    if action.type == "type" and "password" in action.text.lower():
        return ActionDecision(decision="deny", reason="typing passwords is not allowed")
    return ActionDecision(decision="allow")
```

### `ComputerAction`

A type alias for the discriminated union of all supported action types. The `type` field acts as the discriminator. Use `parse_action()` to validate a raw dict into a typed `ComputerAction`.

Supported action types: `move`, `click`, `double_click`, `triple_click`, `drag`, `scroll`, `mouse_down`, `mouse_up`, `type`, `keypress`, `hotkey`, `hold_key`, `wait`, `screenshot`, `zoom`, `cursor_position`, `release_all`.

```python
from modal_computer_use.models import parse_action

action = parse_action({"type": "click", "x": 100, "y": 200, "button": "left"})
# Returns a ClickAction instance
```

---

### `ActionObservationResult`

**Alpha.** Returned by `observations._experimental_act_until_visual_change()`. Pairs the result of an action batch with the first detected visual change observed on the display.

<ResponseField name="frame" type="ObservationFrame" required>
  The observation frame containing image data and metadata about the detected change.
</ResponseField>

<ResponseField name="elapsed_ms" type="float | None">
  Total round-trip time from when the action was sent to when the frame was received, in milliseconds.
</ResponseField>

**Computed properties:**

| Property | Type | Description |
|---|---|---|
| `action_result` | `dict \| None` | The daemon's action result for the correlated batch. |
| `action_id` | `str \| None` | The action ID that correlates this frame to the request. |
| `change_detected` | `bool \| None` | Whether a visual change was detected before the timeout. |
| `change_timeout_reached` | `bool \| None` | Whether the observation timed out waiting for a change. |
| `timings` | `dict` | Timing breakdown including change detection and screenshot daemon timing. |

<Warning>
`ActionObservationResult` is part of an **Alpha** interface. It does not establish semantic application readiness, visual stability, or safety of the next action. Parameters, behavior, and result interpretation may change without notice.
</Warning>

## Sandbox and session

### `ComputerStatus`

Returned by `computer.lifecycle.status()`. Provides a point-in-time snapshot of the desktop's health and remaining budgets.

<ResponseField name="status" type='"starting" | "running" | "stopped" | "degraded" | "failed"' required>
  Current lifecycle state of the desktop.
</ResponseField>

<ResponseField name="ready" type="bool" required>
  Whether the desktop is accepting actions.
</ResponseField>

<ResponseField name="display" type="str" required>
  X11 display string (e.g. `":99"`).
</ResponseField>

<ResponseField name="width" type="int" required>
  Desktop width in pixels.
</ResponseField>

<ResponseField name="height" type="int" required>
  Desktop height in pixels.
</ResponseField>

<ResponseField name="processes" type="dict[str, ProcessStatus]">
  Status of named daemon-managed processes (display server, window manager, browser, etc.).
</ResponseField>

<ResponseField name="resources" type="dict[str, Any]">
  Resource usage snapshot (CPU, memory) when reported by the daemon.
</ResponseField>

<ResponseField name="budgets" type="dict[str, Any]">
  Remaining budget snapshot. Keys include `actions`, `screenshots`, `artifact_bytes`, and `recording_seconds`. Exhausting any budget raises `BudgetExceededError`.
</ResponseField>

---

### `ComputerSessionHandle`

A frozen, versioned, serializable reconnect token for one SDK-owned Modal desktop. You obtain a handle by calling `computer_sandbox.session_handle()` on an owned `ComputerSandbox` or `AsyncComputerSandbox`, then pass it to a deployed Modal Function.

<ResponseField name="app_name" type="str" required>
  The Modal app name the sandbox belongs to.
</ResponseField>

<ResponseField name="modal_environment" type="str" required>
  The Modal environment (workspace) the sandbox is running in.
</ResponseField>

<ResponseField name="requested_modal_region" type="str" required>
  The region the sandbox was created in. The borrowing Function's `function_region` must exactly match this value.
</ResponseField>

<ResponseField name="ingress" type='"attested-tunnel" | "connect"' required>
  How the SDK connects to the daemon inside the sandbox.
</ResponseField>

<ResponseField name="daemon_http_version" type='"1.1" | "2"' required>
  HTTP version used for daemon communication.
</ResponseField>

<ResponseField name="vnc_mode" type='"off" | "view_only"' required>
  noVNC policy on this handle. Control-mode noVNC targets cannot produce handles.
</ResponseField>

<ResponseField name="config_hash" type="str" required>
  16-character hex digest of the sandbox configuration. The borrow validates this against the live session tag before issuing credentials.
</ResponseField>

<Note>
`sandbox_id` and `session_id` are intentionally excluded from `repr()` to avoid accidental logging. They are present in JSON serialization and pickle/cloudpickle because Modal needs them to reconnect. Do not log or publish a `ComputerSessionHandle`.
</Note>

**Borrowing the handle:**

```python
# Synchronous (for synchronous Modal Functions)
with handle.borrow(run_id=run_id, function_region="us-east") as computer:
    screenshot = computer.screenshots.full()

# Asynchronous (preferred for async Modal Functions)
async with handle.borrow_async(run_id=run_id, function_region="us-east") as computer:
    screenshot = await computer.screenshots.full()
```

<ResponseField name="recovery_required" type="bool" required>

<ResponseField name="incident_id" type="str | None">

</ResponseField>

### `SessionRecoveryAcknowledgement`

Returned by `computer_sandbox.acknowledge_recovery()` when the owner successfully acknowledges a recovery incident. After receiving this, new borrows are permitted.

<ResponseField name="recovery_required" type='Literal[False]' required>
  Always `False` after a successful acknowledgement.
</ResponseField>

<ResponseField name="acknowledged" type='Literal[True]' required>
  Always `True` after a successful acknowledgement.
</ResponseField>

### `SessionStartupTiming`

A monotonic, secret-free timing instrument for measuring the cold-start latency of one session request. Construct one before starting a session to record stage-by-stage elapsed times.

```python
from modal_computer_use import SessionStartupTiming

timing = SessionStartupTiming()
# ... connect, authenticate, wait for readiness ...
timing.mark("daemon_ready")
timing.mark("observation_stream_connected")

breakdown = timing.as_dict()
# {"stages": {"daemon_ready": {"status": "observed", "elapsed_ms": 412.3}, ...}}
```

Stages must be marked in monotonic order. Use `.unsupported(stage, reason)` to annotate stages that are not applicable in the current environment (e.g. readiness probes not supported by the installed Modal SDK version).

## Warm pool

### `WarmPoolPolicy`

Defines the desired state for a named warm sandbox pool. Pass this to warm-pool fill and reconcile operations.

<ResponseField name="pool_name" type="str" required>
  Name of the pool. Must be non-empty and produce valid Modal Sandbox slot names when combined with slot indices.
</ResponseField>

<ResponseField name="capacity" type="int" required>
  Target number of warm sandboxes to maintain. Must be between 1 and 100 inclusive.
</ResponseField>

<ResponseField name="min_remaining_seconds" type="int">
  Minimum remaining lifetime (in seconds) required for a warm slot to be considered healthy. Slots expiring sooner than this are rejected as candidates. Defaults to `60`.
</ResponseField>

<ResponseField name="expiry_skew_seconds" type="int">
  Safety buffer subtracted from remaining lifetime before comparing to `min_remaining_seconds`. Defaults to `15`.
</ResponseField>

<ResponseField name="max_claim_scan" type="int">
  Maximum number of warm slots to scan when attempting to claim one. Defaults to `4`.
</ResponseField>

<Warning>
`WarmPoolPolicy` does not support `ComputerConfig` with `idle_timeout_seconds` or explicit `vnc_password` credentials. Passing either raises `ValueError` from `validate_config()`.
</Warning>
