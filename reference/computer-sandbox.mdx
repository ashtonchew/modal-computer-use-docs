`ComputerSandbox` is the primary synchronous class for provisioning and controlling a remotely controllable Linux desktop sandbox hosted on Modal. You construct instances through one of three class methods — `create()`, `attach()`, or `attach_or_create()` — each of which returns a ready `ComputerSandbox` instance and optionally acts as a context manager. The instance exposes typed namespaces (`mouse`, `keyboard`, `screenshots`, etc.) that map directly to the in-sandbox daemon API. When used as a context manager, `ComputerSandbox` automatically handles cleanup according to its lifecycle ownership: sandboxes you created are terminated on exit, sandboxes you only attached to are safely detached without termination.

```python
from modal_computer_use import ComputerConfig, ComputerSandbox

with ComputerSandbox.create(config=ComputerConfig()) as computer:
    computer.mouse.move(320, 240)
    screenshot = computer.screenshots.full()
    screenshot.save("screenshot.png")
```

---

## Installation

`ComputerSandbox.create()` and `ComputerSandbox.attach()` require the Modal extra:

```bash
uv add "modal-computer-use[modal]"
```

Core imports are usable without Modal installed. Entering a provisioning context requires the Modal extra.

---

## Lifecycle Modes

Every `ComputerSandbox` instance carries one of four internal lifecycle modes that determine what happens when you exit a `with` block or call cleanup methods explicitly:

| Mode | How it is set | Context-exit behavior |
|---|---|---|
| `owned` | Returned by `create()` | Terminates, detaches, and closes the client |
| `attached` | Returned by `attach()` or existing-target `attach_or_create()` | Detaches and closes the client — does **not** terminate the sandbox |
| `local` | Returned by `ComputerSandbox.local()` | Closes only the daemon connection |
| `detached` | After an explicit `detach()` call | No further cleanup |

Calling `detach()` explicitly before the `with` block exits transfers lifecycle ownership to your code and prevents the context manager from terminating or detaching the sandbox for you.

## Class Methods

### `ComputerSandbox.create()`

Creates a new Modal sandbox, waits for the daemon to become ready, and returns a `ComputerSandbox` in `owned` mode. Pass `wait=False` to return immediately after the connection token is issued without polling daemon readiness.

```python
ComputerSandbox.create(
    *,
    config: ComputerConfig | None = None,
    app_name: str = "modal-computer-use",
    name: str | None = None,
    image: object | None = None,
    expose_vnc: bool | str | None = None,
    tags: dict[str, str] | None = None,
    app_tags: dict[str, str] | None = None,
    secrets: list[object] | None = None,
    volumes: dict[str, object] | None = None,
    owner: str | None = None,
    wait: bool = True,
    **sandbox_kwargs,
) -> ComputerSandbox
```

<ParamField path="config" type="ComputerConfig | None" default="ComputerConfig()">
  Desktop configuration — resolution, resources, browser, networking, and ingress settings. Defaults to a standard-profile sandbox when omitted.
</ParamField>

<ParamField path="app_name" type="str" default="modal-computer-use">
  Modal App name to look up or create. The SDK scopes sandbox ownership to this app.
</ParamField>

<ParamField path="name" type="str | None">
  Optional Modal sandbox name. When set, Modal enforces uniqueness within the app. Use `attach_or_create()` for named acquisition with race-safe creation.
</ParamField>

<ParamField path="image" type="object | None">
  Custom Modal `Image` object. Defaults to the image selected by `config.image` and `config.resources.profile`.
</ParamField>

<ParamField path="expose_vnc" type="bool | str | None">
  VNC exposure override. Accepts `True` (view-only), `False` (off), or `"control"` (full control). Takes precedence over `config.expose_vnc`.
</ParamField>

<ParamField path="tags" type="dict[str, str] | None">
  Additional sandbox tags merged on top of SDK-managed tags. SDK-owned fields (`computer-use.*`) cannot be overridden here.
</ParamField>

<ParamField path="app_tags" type="dict[str, str] | None">
  Tags applied to the Modal App object rather than the sandbox.
</ParamField>

<ParamField path="secrets" type="list[object] | None">
  List of Modal `Secret` objects mounted into the sandbox.
</ParamField>

<ParamField path="volumes" type="dict[str, object] | None">
  Mapping of mount-path strings to Modal `Volume` or `ModalVolumeMount` objects. Use `ModalVolumeMount` to control read-only access or sub-path mounting.
</ParamField>

<ParamField path="owner" type="str | None">
  Optional owner identifier written to `computer-use.owner`. Used by `ComputerSandboxManager.cleanup_expired(owner=...)` to scope bulk cleanup.
</ParamField>

<ParamField path="wait" type="bool" default="True">
  When `True`, blocks until Modal's sandbox readiness probe passes **and** the daemon `/readyz` endpoint reports ready. When `False`, returns after the connection token is issued without polling readiness.
</ParamField>

<ParamField path="**sandbox_kwargs">
  Additional keyword arguments forwarded to `modal.Sandbox.create()`. SDK-owned fields (`app`, `block_network`, `encrypted_ports`, `env`, `h2_ports`, `inbound_cidr_allowlist`, `outbound_cidr_allowlist`, `outbound_domain_allowlist`, `readiness_probe`, `tags`) are rejected; all other Modal arguments pass through.
</ParamField>

<CodeGroup>
```python Basic creation
from modal_computer_use import ComputerConfig, ComputerSandbox

with ComputerSandbox.create(config=ComputerConfig()) as computer:
    screenshot = computer.screenshots.full()
    screenshot.save("output.png")
# Sandbox is automatically terminated when the block exits.
```

```python Browser profile
from modal_computer_use import (
    BrowserConfig,
    ComputerConfig,
    ComputerSandbox,
    ResourceConfig,
)

config = ComputerConfig(
    resources=ResourceConfig(profile="browser"),
    browser=BrowserConfig(kind="chromium"),
)

with ComputerSandbox.create(config=config) as computer:
    computer.browser.open_url("https://example.com")
    screenshot = computer.screenshots.full()
```

```python Non-blocking creation
computer = ComputerSandbox.create(wait=False)
# The connection token is ready, but the daemon may not be.
# Poll readiness manually before sending actions.
computer.wait_until_ready()
```
</CodeGroup>

<Warning>
  `create()` rejects overrides of SDK-owned Modal fields such as `app`, `env`, `readiness_probe`, `encrypted_ports`, and all `computer-use.*` tag names. Passing any of these through `**sandbox_kwargs` raises a `ValueError` immediately.
</Warning>

### `ComputerSandbox.attach()`

Attaches to an existing sandbox or daemon without taking lifecycle ownership. Returns a `ComputerSandbox` in `attached` mode. By default `wait=False`, so you receive the client immediately without polling daemon readiness — useful when you only need metadata or want to terminate the sandbox without waiting for it to be ready.

```python
ComputerSandbox.attach(
    *,
    sandbox_id: str | None = None,
    name: str | None = None,
    run_id: str | None = None,
    base_url: str | None = None,
    token: str | None = None,
    app_name: str = "modal-computer-use",
    ingress: ModalIngress = "attested-tunnel",
    http2: bool = False,
    wait: bool = False,
    readiness_timeout: float = 120.0,
    modal_environment: str | None = None,
    allow_legacy_unscoped: bool = False,
) -> ComputerSandbox
```

Pass **exactly one** of `sandbox_id`, `name`, `run_id`, or `base_url`. The `token` parameter is valid only with `base_url`.

<ParamField path="sandbox_id" type="str | None">
  Attach by Modal sandbox object ID (e.g. `"sb-abc123"`). The SDK verifies the sandbox belongs to `app_name`.
</ParamField>

<ParamField path="name" type="str | None">
  Attach to a sandbox by its Modal app-scoped name.
</ParamField>

<ParamField path="run_id" type="str | None">
  Attach to a sandbox by its `computer-use.run_id` tag value. Raises `SandboxAmbiguousError` if multiple sandboxes share the same run ID.
</ParamField>

<ParamField path="base_url" type="str | None">
  Attach directly to an already-running daemon at this URL. Skips all Modal API calls. Use `token` to supply bearer credentials.
</ParamField>

<ParamField path="token" type="str | None">
  Bearer token for direct `base_url` attachment. Invalid with Modal-backed selectors.
</ParamField>

<ParamField path="wait" type="bool" default="False">
  When `True`, polls `/readyz` after attaching and raises `TimeoutError` if the daemon is not ready within `readiness_timeout` seconds. A timeout closes the client but does **not** terminate the existing sandbox.
</ParamField>

<ParamField path="readiness_timeout" type="float" default="120.0">
  Seconds to wait for daemon readiness when `wait=True`.
</ParamField>

<ParamField path="allow_legacy_unscoped" type="bool" default="False">
  Set to `True` only while migrating a sandbox that was created before the app-scoping tag was introduced. A conflicting or mismatched app tag always fails regardless of this flag.
</ParamField>

<CodeGroup>
```python Attach by sandbox ID
from modal_computer_use import ComputerSandbox

with ComputerSandbox.attach(sandbox_id="sb-abc123", wait=True) as computer:
    screenshot = computer.screenshots.full()
# Sandbox keeps running after the block exits.
```

```python Attach by run ID
computer = ComputerSandbox.attach(
    run_id="support-ticket-42",
    wait=True,
    readiness_timeout=60.0,
)
screenshot = computer.screenshots.full()
computer.detach()
```

```python Attach by direct URL
with ComputerSandbox.attach(
    base_url="https://your-daemon.example.com",
    token="my-bearer-token",
) as computer:
    computer.wait_until_ready()
    computer.mouse.click(100, 200)
```
</CodeGroup>

### `ComputerSandbox.attach_or_create()`

Attempts to attach to a sandbox with the given `name`. If no sandbox with that name exists (`NotFoundError`), creates one using the provided `config`. If a competing process creates the same name simultaneously (`AlreadyExistsError`), the SDK performs a bounded retry to discover the winner. Existing targets must carry the expected app and config-hash tags; hash mismatches raise `ConfigConflictError`.

```python
ComputerSandbox.attach_or_create(
    *,
    name: str,
    config: ComputerConfig | None = None,
    app_name: str = "modal-computer-use",
    run_id: str | None = None,
    image: object | None = None,
    expose_vnc: bool | str | None = None,
    tags: dict[str, str] | None = None,
    app_tags: dict[str, str] | None = None,
    secrets: list[object] | None = None,
    volumes: dict[str, object] | None = None,
    owner: str | None = None,
    wait: bool = True,
    readiness_timeout: float | None = None,
    **sandbox_kwargs,
) -> ComputerSandbox
```

<ParamField path="name" type="str" required>
  Modal app-scoped live allocation key. This is the name used for sandbox uniqueness and future re-attachment.
</ParamField>

<ParamField path="config" type="ComputerConfig | None">
  Desktop configuration. Used for creation and for generating the config hash that validates an existing target. Defaults to `ComputerConfig()`.
</ParamField>

<ParamField path="run_id" type="str | None">
  Optional run ID to embed in the sandbox tags. Available as `computer.metadata().run_id` and for later `attach(run_id=...)` lookups. Cannot conflict with `config.run_id` if both are provided.
</ParamField>

<ParamField path="wait" type="bool" default="True">
  Whether to poll daemon readiness for both the creation and attachment branches.
</ParamField>

<Note>
  Creation arguments (`image`, `tags`, `secrets`, `volumes`, `expose_vnc`, `owner`, `**sandbox_kwargs`) are validated before acquisition but apply **only** when this call creates the sandbox. They do not mutate an existing target and do not participate in its compatibility check.
</Note>

```python
from modal_computer_use import ComputerConfig, ComputerSandbox

# First call: creates the sandbox.
# Second call: attaches to the same sandbox without terminating it.
computer = ComputerSandbox.attach_or_create(
    name="support-desktop",
    config=ComputerConfig(),
)
try:
    screenshot = computer.screenshots.full()
finally:
    computer.detach()  # Keep the sandbox running for re-use.
```

## Instance Methods

### `wait_until_ready(timeout, interval)`

Polls the daemon's `/readyz` endpoint until it reports `{"ready": true}` or the timeout expires. Raises `TimeoutError` with a detail message if the deadline is reached.

```python
computer.wait_until_ready(timeout=120.0, interval=1.0)
```

<ParamField path="timeout" type="float" default="120.0">
  Maximum seconds to wait before raising `TimeoutError`.
</ParamField>

<ParamField path="interval" type="float" default="1.0">
  Polling interval in seconds.
</ParamField>

---

### `detach()`

Transfers lifecycle ownership to your code, closes the local Modal sandbox handle, and closes the HTTP client. After calling `detach()`, the context manager no longer terminates the sandbox on exit.

```python
computer = ComputerSandbox.create(config=ComputerConfig())
try:
    # Do your work.
    screenshot = computer.screenshots.full()
finally:
    computer.detach()
# Sandbox continues running. You are responsible for terminating it later.
```

<Warning>
  After `detach()` the `ComputerSandbox` instance is in `detached` mode and can no longer send requests. Store the `sandbox_id` from `computer.metadata()` before detaching if you need to re-attach later.
</Warning>

---

### `terminate(wait=False)`

Terminates the Modal sandbox backing this instance. When called on an attached sandbox, this stops the remote machine. Pass `wait=True` to block until the sandbox has fully stopped.

```python
computer.terminate(wait=True)
```

<ParamField path="wait" type="bool" default="False">
  Block until the sandbox is fully terminated. When `False`, the termination request is sent asynchronously.
</ParamField>

---

### `metadata()`

Returns a `SandboxRef` with Modal metadata for this sandbox, or `None` for `local`-mode instances. The `SandboxRef` contains:

<ResponseField name="sandbox_id" type="str">
  Modal sandbox object ID (e.g. `"sb-abc123"`).
</ResponseField>

<ResponseField name="app_name" type="str">
  Modal App name this sandbox belongs to.
</ResponseField>

<ResponseField name="name" type="str | None">
  Named allocation key, if one was set.
</ResponseField>

<ResponseField name="run_id" type="str | None">
  `computer-use.run_id` tag value, used as the correlation ID for this sandbox's lifetime.
</ResponseField>

<ResponseField name="owner" type="str | None">
  `computer-use.owner` tag value, if one was set.
</ResponseField>

<ResponseField name="created_at" type="datetime | None">
  Sandbox creation timestamp parsed from tags.
</ResponseField>

<ResponseField name="config_hash" type="str | None">
  SHA-256 config hash embedded in tags at creation time. Used to validate `attach_or_create()` compatibility.
</ResponseField>

<ResponseField name="tags" type="dict[str, str]">
  All sandbox tags at the time metadata was resolved.
</ResponseField>

```python
meta = computer.metadata()
if meta:
    print(meta.sandbox_id, meta.run_id)
```

---

### `session_handle()`

Returns a frozen `ComputerSessionHandle` for this SDK-owned Modal desktop. The handle encodes routing identity — sandbox/session ID, app name, Modal environment, region, ingress, daemon HTTP version, VNC policy, and config hash — and can be passed to a deployed Modal Function for a `borrow_async()` session handoff.

```python
handle = computer.session_handle()
# Pass `handle` to a Modal Function for a borrow_async() trajectory.
```

<Note>
  `session_handle()` requires that the sandbox was created (not just attached), that an explicit `modal_region` and `modal_environment` were set in the config, and that `vnc_mode` is `"off"` or `"view_only"`. Control-mode noVNC sandboxes cannot produce a handoff handle.
</Note>

---

### `debug_urls()`

Returns a `DebugUrls` object containing the noVNC URL (if VNC is enabled), daemon URL, and recording dashboard URL for this sandbox.

```python
urls = computer.debug_urls()
if urls.vnc:
    print("noVNC:", urls.vnc)
```

<Note>
  For Modal-backed sandboxes, call `computer.debug_urls()` rather than `computer.debug.urls()` to ensure the noVNC URL from Modal orchestration is included.
</Note>

---

### `reload_volumes(timeout=55)`

Blocks until every mounted Modal Volume has finished reloading, or raises an error if the timeout expires. Use this to pick up files written from outside the sandbox (e.g. from another Modal Function).

```python
computer.reload_volumes(timeout=55)
```

<ParamField path="timeout" type="int" default="55">
  Maximum seconds to wait for all volumes to reload.
</ParamField>

---

### `snapshot_directory(path, timeout, ttl)`

Snapshots a directory inside the sandbox as a Modal Image. The returned image can be restored to a fresh sandbox via `mount_image()`.

```python
snapshot = computer.snapshot_directory(
    "/home/desktop/artifacts",
    timeout=55,
)
```

<ParamField path="path" type="str" default="/home/desktop/artifacts">
  Absolute POSIX path of the directory to snapshot.
</ParamField>

<ParamField path="timeout" type="int" default="55">
  Maximum seconds to wait for the snapshot operation.
</ParamField>

<ParamField path="ttl" type="int | None" default="2592000">
  Snapshot retention in seconds (default 30 days). Pass `None` for no expiry.
</ParamField>

---

### `mount_image(path, image)`

Mounts a Modal Image into the running sandbox at the given path. Use this to restore a previously created directory snapshot.

```python
computer.mount_image("/home/desktop/artifacts", snapshot)
```

<ParamField path="path" type="str" required>
  Absolute POSIX path inside the sandbox where the image will be mounted.
</ParamField>

<ParamField path="image" type="object" required>
  A Modal `Image` object, typically returned by a prior `snapshot_directory()` call.
</ParamField>

---

### `recovery_status()`

Returns a `SessionRecoveryStatus` object describing durable target recovery state. Requires the original SDK-owned daemon bearer credential; attached instances without the owner proof raise `SandboxUnavailableError`.

```python
status = computer.recovery_status()
```

---

### `acknowledge_recovery(incident_id)`

Acknowledges one specific recovery incident as the original owner. Requires the original owner proof.

```python
computer.acknowledge_recovery(incident_id="incident-abc123")
```

<ParamField path="incident_id" type="str" required>
  Non-empty string identifying the specific recovery incident to acknowledge.
</ParamField>

## Context Manager Ownership Rules

<Tabs>
  <Tab title="create() — owns the sandbox">
    ```python
    with ComputerSandbox.create(config=ComputerConfig()) as computer:
        computer.mouse.click(320, 240)
    # On exit: terminate() → detach() → client.close()
    ```
    The SDK terminates the Modal sandbox, detaches the handle, and closes the HTTP client.
  </Tab>
  <Tab title="attach() — does not own the sandbox">
    ```python
    with ComputerSandbox.attach(sandbox_id="sb-abc123", wait=True) as computer:
        computer.mouse.click(320, 240)
    # On exit: detach() → client.close() — sandbox keeps running
    ```
    Exiting only detaches the local handle and closes the HTTP client. The remote sandbox continues running.
  </Tab>
  <Tab title="explicit detach() — transfers ownership">
    ```python
    with ComputerSandbox.create(config=ComputerConfig()) as computer:
        # Do setup work, then hand off lifecycle to your own code.
        handle = computer.session_handle()
        computer.detach()   # Prevents context-exit from terminating the sandbox.
    # On exit: no-op (mode is now "detached")
    ```
    After `detach()`, you are responsible for eventually calling `terminate()`.
  </Tab>
</Tabs>
