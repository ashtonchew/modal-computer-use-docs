The typed Python SDK runs over the daemon HTTP API. Choose the entry point that matches lifecycle ownership.

## Choose an entry point

| Need | Entry point | Ownership |
| --- | --- | --- |
| Run the optimized placed trajectory | `AsyncComputerSandbox.create()` and `ComputerSessionHandle.borrow_async()` | The async owner keeps the Sandbox. The placed Function borrows it. |
| Use an explicit unplaced compatibility path | `AsyncComputerSandbox.create_unplaced()` | The caller owns the Sandbox and topology. |
| Use synchronous Modal primitives | `ComputerSandbox` | Created desktops are owned. Attached desktops are not. |
| Connect to an existing daemon | `DaemonClient` or `AsyncDaemonClient` | Closing the client closes its connections. |
| Manage several desktops | `ComputerSandboxManager` | Lifecycle actions remain explicit. |

The sync and async borrowed clients both expose `computer.step(actions)`. The async path is the primary model-loop surface.

## Import boundary

Import stable SDK types from `modal_computer_use`.

```python
from modal_computer_use import (
    AsyncComputerSandbox,
    ComputerConfig,
    ComputerStepResult,
    Screenshot,
)
```

Core imports stay provider-free. Install only the Modal, OpenAI, or Anthropic extras your
application uses.

## Daemon boundary

The daemon owns desktop primitives, native input, capture, batching, receipts, and cleanup. The application owns model calls and provider state. Modal orchestration stays in the SDK owner and handoff surfaces.

Use [OpenAPI](/reference/openapi) for the HTTP contract. Use [Namespaces](/reference/namespaces) for Python methods. The [application API guide](https://github.com/ashtonchew/modal-computer-use/blob/b60c1cb7495200e36a738c0f6e07961b1d2db93c/docs/api.md) records the complete lifecycle and recovery contract.
