The `computer.mouse`, `computer.keyboard`, `computer.clipboard`, and `computer.input` namespaces give you precise, low-level control over all user-input surfaces in the Sandbox desktop. Mouse methods emit XTest pointer events; keyboard methods use the configured input backend (XTest/XKB by default, with `xdotool` as a legacy fallback); clipboard methods read and write the X clipboard directly. Every mutating call holds the daemon's input lock, so batched actions and direct calls do not race.

<Note>
All methods shown here are available as `async` counterparts on `AsyncComputerSandbox` and `AsyncDaemonClient`. The async versions are identical in signature but must be awaited.
</Note>

## computer.mouse

The `computer.mouse` namespace controls pointer position, clicks, drags, scrolling, and explicit button press/release cycles.

### `move(x, y)`

Moves the cursor to the specified desktop coordinates.

<ParamField path="x" type="int" required>
  Destination X coordinate in pixels, measured from the left edge of the display.
</ParamField>

<ParamField path="y" type="int" required>
  Destination Y coordinate in pixels, measured from the top edge of the display.
</ParamField>

**Returns** `Point` — the resolved cursor position after the move.

```python
point = computer.mouse.move(640, 400)
print(point.x, point.y)
```

---

### `click(x, y, button="left")`

Moves the cursor to the given coordinates and performs a button click.

<ParamField path="x" type="int | None" default="None">
  X coordinate to click. When `None`, clicks at the current cursor position.
</ParamField>

<ParamField path="y" type="int | None" default="None">
  Y coordinate to click. When `None`, clicks at the current cursor position.
</ParamField>

<ParamField path="button" type='"left" | "middle" | "right"' default='"left"'>
  Mouse button to click.
</ParamField>

<ParamField path="double" type="bool" default="false">
  Perform a double-click instead of a single click.
</ParamField>

<ParamField path="modifiers" type="list[str] | None" default="None">
  Keyboard modifiers to hold during the click (for example `["shift"]` or `["ctrl", "alt"]`).
</ParamField>

**Returns** `Point` — the resolved cursor position after the click.

```python
# Left-click a button
computer.mouse.click(320, 240)

# Right-click with Shift held
computer.mouse.click(100, 200, button="right", modifiers=["shift"])
```

---

### `drag(start_x, start_y, end_x, end_y, ...)`

Performs a click-and-drag from a start position to an end position, optionally following a custom path of waypoints.

<ParamField path="start_x" type="int | None" default="None">
  X coordinate of the drag start point. When `None`, the drag starts at the current cursor position.
</ParamField>

<ParamField path="start_y" type="int | None" default="None">
  Y coordinate of the drag start point.
</ParamField>

<ParamField path="end_x" type="int | None" default="None">
  X coordinate of the drag end point.
</ParamField>

<ParamField path="end_y" type="int | None" default="None">
  Y coordinate of the drag end point.
</ParamField>

<ParamField path="path" type="list[Point] | None" default="None">
  Ordered list of intermediate waypoints through which the drag travels. Each element is a `Point` with `x` and `y` fields. The maximum number of points is `1024` by default (configurable via `COMPUTER_USE_MAX_DRAG_POINTS`).
</ParamField>

<ParamField path="button" type='"left" | "middle" | "right"' default='"left"'>
  Mouse button held during the drag.
</ParamField>

<ParamField path="duration_ms" type="int" default="500">
  Total duration of the drag animation in milliseconds.
</ParamField>

<ParamField path="modifiers" type="list[str] | None" default="None">
  Keyboard modifiers to hold during the drag.
</ParamField>

**Returns** `Point` — the resolved cursor position after the drag completes.

```python
from modal_computer_use.models import Point

# Simple drag
computer.mouse.drag(100, 100, 400, 300)

# Drag along a curved path
computer.mouse.drag(
    100, 100, 400, 300,
    path=[Point(x=200, y=150), Point(x=300, y=200)],
    duration_ms=800,
)
```

---

### `scroll(direction, amount, x, y)`

Scrolls at the specified position.

<ParamField path="direction" type='"up" | "down" | "left" | "right"' required>
  Scroll direction.
</ParamField>

<ParamField path="amount" type="int" default="1">
  Number of scroll units (wheel clicks) to emit.
</ParamField>

<ParamField path="x" type="int | None" default="None">
  X coordinate of the scroll target. When `None`, scrolls at the current cursor position.
</ParamField>

<ParamField path="y" type="int | None" default="None">
  Y coordinate of the scroll target.
</ParamField>

**Returns** `ActionResult`.

```python
computer.mouse.scroll("down", amount=3, x=640, y=400)
```

---

### `down(button, x, y)`

Presses a mouse button without releasing it. Use `up()` to release. Useful for constructing custom drag sequences when the `drag()` method's path interpolation is not sufficient.

<ParamField path="button" type='"left" | "middle" | "right"' default='"left"'>
  Mouse button to press.
</ParamField>

<ParamField path="x" type="int | None" default="None">
  X coordinate to move to before pressing. When `None`, presses at the current cursor position.
</ParamField>

<ParamField path="y" type="int | None" default="None">
  Y coordinate to move to before pressing.
</ParamField>

**Returns** `ActionResult`.

<Warning>
Always pair `down()` with a matching `up()`. If the daemon session ends with a button held, call `computer.input.release_all()` to clean up state.
</Warning>

---

### `up(button, x, y)`

Releases a mouse button that was previously pressed with `down()`.

<ParamField path="button" type='"left" | "middle" | "right"' default='"left"'>
  Mouse button to release.
</ParamField>

<ParamField path="x" type="int | None" default="None">
  X coordinate to move to before releasing.
</ParamField>

<ParamField path="y" type="int | None" default="None">
  Y coordinate to move to before releasing.
</ParamField>

**Returns** `ActionResult`.

---

### `position()`

Reads the current cursor position without moving it.

**Returns** `Point` — the current cursor coordinates.

```python
pos = computer.mouse.position()
print(f"Cursor is at ({pos.x}, {pos.y})")
```

## computer.keyboard

The `computer.keyboard` namespace types text, presses individual keys, sends hotkeys, and holds modifier keys around nested action sequences.

### `type(text, method="auto")`

Types a string of text into the currently focused input target.

<ParamField path="text" type="str" required>
  The text string to type. Long or unmapped Unicode text is automatically routed through the clipboard when `method="auto"`.
</ParamField>

<ParamField path="delay_ms" type="int" default="10">
  Delay in milliseconds between individual keystrokes when using native keystroke input.
</ParamField>

<ParamField path="method" type='"auto" | "keystrokes" | "clipboard" | "xdotool"' default='"auto"'>
  Input method to use:

  - `"auto"` — Default. Uses native keystrokes for characters the active keyboard layout can map and switches to clipboard paste for long text or unmapped Unicode characters.
  - `"keystrokes"` — Always uses native XTest/XKB keystroke emission. Emits text in bounded chunks.
  - `"clipboard"` — Always pastes via the clipboard. Useful for large text blocks or characters that cannot be mapped to keysyms.
  - `"xdotool"` — Legacy explicit compatibility request; use only when the target application requires `xdotool` behavior.
</ParamField>

**Returns** `ActionResult`.

```python
computer.keyboard.type("Hello, World!")

# Force clipboard paste for Unicode-heavy text
computer.keyboard.type("こんにちは", method="clipboard")
```

---

### `press(key, modifiers=None, duration_ms=0)`

Presses and releases a single key, optionally with modifier keys held.

<ParamField path="key" type="str" required>
  Key name to press (for example `"Return"`, `"Escape"`, `"Tab"`, `"a"`, `"F5"`). Use `supported_keys()` to list all valid names.
</ParamField>

<ParamField path="modifiers" type="list[str] | None" default="None">
  Modifier keys to hold during the press (for example `["ctrl"]`, `["shift", "alt"]`).
</ParamField>

<ParamField path="duration_ms" type="int" default="0">
  How long to hold the key down in milliseconds before releasing.
</ParamField>

**Returns** `ActionResult`.

```python
# Press Enter
computer.keyboard.press("Return")

# Ctrl+C
computer.keyboard.press("c", modifiers=["ctrl"])
```

---

### `hotkey(*keys, duration_ms=0)`

Presses multiple keys simultaneously as a chord, then releases them together.

<ParamField path="keys" type="str (variadic)" required>
  One or more key names to press simultaneously. The maximum collection size is `64` by default (configurable via `COMPUTER_USE_MAX_KEY_COLLECTION_SIZE`).
</ParamField>

<ParamField path="duration_ms" type="int" default="0">
  How long to hold the chord before releasing.
</ParamField>

**Returns** `ActionResult`.

```python
# Ctrl+Shift+Escape
computer.keyboard.hotkey("ctrl", "shift", "Escape")
```

---

### `hold(key, duration_ms=None)`

Holds a key down for a specified duration. In action batches (via `computer.actions.run()`), `hold_key` supports nested actions that execute while the key is held. The direct `hold()` primitive route accepts only `key` and `duration_ms` — it does not support nested action trees.

<ParamField path="key" type="str" required>
  Key name to hold.
</ParamField>

<ParamField path="duration_ms" type="int | None" default="None">
  Duration in milliseconds to hold the key. When `None`, uses the daemon default action timeout.
</ParamField>

**Returns** `ActionResult`.

<Tip>
For complex key-hold sequences with nested mouse or keyboard actions, use the `hold_key` action type through `computer.actions.run()` rather than this direct primitive.
</Tip>

---

### `supported_keys()`

Returns the full map of key names the daemon accepts.

**Returns** `dict[str, str]` — a mapping of key name to its canonical XKB/keysym description.

```python
keys = computer.keyboard.supported_keys()
# keys["Return"] -> "Return key"
```

## computer.clipboard

The `computer.clipboard` namespace reads and writes the X clipboard directly, independent of keyboard input.

### `get_text()`

Reads the current text content of the clipboard.

**Returns** `str` — the clipboard text, or an empty string if the clipboard is empty.

```python
text = computer.clipboard.get_text()
print(text)
```

---

### `set_text(text)`

Writes a string to the clipboard.

<ParamField path="text" type="str" required>
  Text to place in the clipboard. Subject to the 16 MiB JSON envelope limit.
</ParamField>

**Returns** `ActionResult`.

```python
computer.clipboard.set_text("text to paste later")
```

---

### `clear()`

Clears the clipboard contents.

**Returns** `ActionResult`.

```python
computer.clipboard.clear()
```

## computer.input

The `computer.input` namespace provides safety utilities for cleaning up held input state.

### `release_all()`

Releases all currently held keys and mouse buttons. Call this after an error or exception to ensure the desktop is not left with keys or buttons stuck down.

**Returns** `ActionResult` — on success, `output.keys` lists the keys that were released and `output.buttons` lists the buttons that were released.

If cleanup is incomplete, the call fails with `code="release_all_incomplete"`. The `output.remaining` field lists controls that are still held, and `output.failures` contains bounded per-control failure metadata.

```python
try:
    computer.mouse.down()
    computer.keyboard.press("shift")
    # ... some actions ...
except Exception:
    result = computer.input.release_all()
```

## Input error codes

When an input operation fails, the daemon returns a structured error with a `code` field. Batch item failures use the same `code` as `error_code` and place `{"code": code, ...details}` in the `output` field.

| Code | HTTP status | Meaning |
|---|:---:|---|
| `input_backend_unavailable` | 503 | Input emission did not start. The `details` field identifies the selected `input_backend`. `retry_safe=true` and `emission_state="not_started"`. |
| `input_may_be_partial` | 500 | Input emission may have started. The `details` field identifies the selected `input_backend` and sets `emission_state="possibly_partial"`. `retry_safe=false` for presses, typing, clicks, and drags; `retry_safe=true` for idempotent key/button releases. |
| `input_state_conflict` | 409 | The target key or button was already held, so emission did not start. Release or change the conflicting state before retrying. |

<Warning>
`retry_safe` describes duplicate-execution safety only. It is not a promise that the condition is transient or a recommendation to automatically retry. Do not replay an `input_may_be_partial` press, type, click, or drag operation through a different adapter — doing so may double the original input.
</Warning>
