`AsyncComputerSandbox` is the native async counterpart to `ComputerSandbox`. It provisions, attaches to, and controls Modal Linux desktop sandboxes without blocking the event loop. All three construction methods — `create()`, `attach()`, and `attach_or_create()` — return lazy async context managers that perform no Modal work until you enter them with `async with`. The sandbox is ready to receive actions the moment the context yields. The same typed namespaces available on `ComputerSandbox` (`mouse`, `keyboard`, `screenshots`, etc.) are exposed directly on the instance, and all operations are `await`-able throughout.

```python
import asyncio
from modal_computer_use import AsyncComputerSandbox, ComputerConfig

async def main() -> None:
    async with AsyncComputerSandbox.create(config=ComputerConfig()) as computer:
        await computer.mouse.move(320, 240)
        screenshot = await computer.screenshots.full()
        screenshot.save("output.png")

asyncio.run(main())
```

---

## Installation

All three class methods require the Modal extra:

```bash
uv add "modal-computer-use[modal]"
```

Core imports are usable without Modal installed. Entering a provisioning context requires the Modal extra.

---

## Differences from `ComputerSandbox`

| Feature | `ComputerSandbox` | `AsyncComputerSandbox` |
|---|---|---|
| Execution model | Blocking (synchronous) | Non-blocking (`await`-able) |
| Context manager | `with` | `async with` |
| `wait=False` option | ✓ on `create()` and `attach()` | Not exposed — contexts always yield a ready sandbox |
| Modal API calls | Synchronous | Uses `.aio` variants throughout |
| `local()` direct URL connection | Handled by `ComputerSandbox.local()` | Use `AsyncDaemonClient.local()` instead |
| `wait_until_ready()` | Sync polling | `await computer.wait_until_ready()` via `AsyncDaemonClient` |

`AsyncComputerSandbox` does not expose `wait=False`. Every context manager entry blocks the event loop only for cooperative async I/O and yields a daemon that is confirmed ready when the `async with` block starts.

---

## Lifecycle Modes

The same ownership rules that apply to `ComputerSandbox` apply here:

| Mode | How it is set | Context-exit behavior |
|---|---|---|
| `owned` | Returned by `create()` | Terminates, detaches, and closes |
| `attached` | Returned by `attach()` or existing-target `attach_or_create()` | Detaches and closes — does **not** terminate |

Calling `await computer.detach()` explicitly before the context exits transfers lifecycle ownership to your code and prevents termination on exit. Any failure during `create()` automatically terminates and detaches the partially-allocated sandbox before re-raising the error.

## Class Methods

### `AsyncComputerSandbox.create()`

Returns a lazy `async with` context manager. Modal work begins on entry and the sandbox is daemon-ready when the context yields. Internally uses `modal.App.lookup.aio`, `modal.Sandbox.create.aio`, and `sandbox.wait_until_ready.aio`.

```python
AsyncComputerSandbox.create(
    *,
    config: ComputerConfig | None = None,
    app_name: str = "modal-computer-use",
    name: str | None = None,
    image: object | None = None,
    expose_vnc: bool | str | None = None,
    tags: Mapping[str, str] | None = None,
    app_tags: Mapping[str, str] | None = None,
    secrets: Sequence[object] | None = None,
    volumes: Mapping[str, object] | None = None,
    owner: str | None = None,
    **sandbox_kwargs,
) -> AsyncContextManager[AsyncComputerSandbox]
```

<ParamField path="config" type="ComputerConfig | None" default="ComputerConfig()">
  Desktop configuration — resolution, resources, browser, networking, and ingress settings.
</ParamField>

<ParamField path="app_name" type="str" default="modal-computer-use">
  Modal App name to look up or create.
</ParamField>

<ParamField path="name" type="str | None">
  Optional Modal sandbox name. Use `attach_or_create()` for named acquisition with race-safe creation semantics.
</ParamField>

<ParamField path="image" type="object | None">
  Custom Modal `Image` object. Defaults to the image selected by `config`.
</ParamField>

<ParamField path="expose_vnc" type="bool | str | None">
  VNC exposure override. Accepts `True` (view-only), `False` (off), or `"control"` (full control).
</ParamField>

<ParamField path="tags" type="Mapping[str, str] | None">
  Additional sandbox tags merged on top of SDK-managed tags.
</ParamField>

<ParamField path="secrets" type="Sequence[object] | None">
  Modal `Secret` objects mounted into the sandbox.
</ParamField>

<ParamField path="volumes" type="Mapping[str, object] | None">
  Mount-path to Modal `Volume` or `ModalVolumeMount` mapping.
</ParamField>

<ParamField path="**sandbox_kwargs">
  Additional keyword arguments forwarded to `modal.Sandbox.create.aio()`. SDK-owned fields are rejected.
</ParamField>

<CodeGroup>
```python Basic creation
import asyncio
from modal_computer_use import AsyncComputerSandbox, ComputerConfig

async def main() -> None:
    async with AsyncComputerSandbox.create(config=ComputerConfig()) as computer:
        await computer.mouse.move(100, 200)

asyncio.run(main())
```

### `AsyncComputerSandbox.attach()`

Returns a lazy `async with` context manager that attaches to an existing sandbox without taking lifecycle ownership. Accepts exactly one Modal selector: `sandbox_id`, `name`, or `run_id`.

```python
AsyncComputerSandbox.attach(
    *,
    sandbox_id: str | None = None,
    name: str | None = None,
    run_id: str | None = None,
    app_name: str = "modal-computer-use",
    ingress: ModalIngress = "attested-tunnel",
    http2: bool = False,
    readiness_timeout: float = 120.0,
    modal_environment: str | None = None,
    allow_legacy_unscoped: bool = False,
) -> AsyncContextManager[AsyncComputerSandbox]
```

<ParamField path="sandbox_id" type="str | None">
  Attach by Modal sandbox object ID.
</ParamField>

<ParamField path="name" type="str | None">
  Attach by Modal app-scoped sandbox name.
</ParamField>

<ParamField path="run_id" type="str | None">
  Attach by `computer-use.run_id` tag value.
</ParamField>

<ParamField path="readiness_timeout" type="float" default="120.0">
  Seconds to wait for daemon readiness on context entry.
</ParamField>

<ParamField path="allow_legacy_unscoped" type="bool" default="False">
  Set to `True` only while migrating a sandbox that predates app-scoping tags.
</ParamField>

<Note>
  Async attachment does not support direct `base_url` connections. For an existing daemon URL, use `AsyncDaemonClient.local()` or `AsyncDaemonClient(base_url=..., token=...)` directly.
</Note>

```python
import asyncio
from modal_computer_use import AsyncComputerSandbox

async def main() -> None:
    async with AsyncComputerSandbox.attach(sandbox_id="sb-abc123") as computer:
        screenshot = await computer.screenshots.full()
    # Sandbox keeps running after the block exits.

asyncio.run(main())
```

### `AsyncComputerSandbox.attach_or_create()`

Returns a lazy `async with` context manager that attaches to a named sandbox or creates it if it does not exist. Uses Modal's `.aio` APIs throughout. Always yields a daemon-ready sandbox on entry. Existing targets must carry the expected app and config-hash tags; hash mismatches raise `ConfigConflictError`.

```python
AsyncComputerSandbox.attach_or_create(
    *,
    name: str,
    config: ComputerConfig | None = None,
    app_name: str = "modal-computer-use",
    run_id: str | None = None,
    image: object | None = None,
    expose_vnc: bool | str | None = None,
    tags: Mapping[str, str] | None = None,
    app_tags: Mapping[str, str] | None = None,
    secrets: Sequence[object] | None = None,
    volumes: Mapping[str, object] | None = None,
    owner: str | None = None,
    **sandbox_kwargs,
) -> AsyncContextManager[AsyncComputerSandbox]
```

<ParamField path="name" type="str" required>
  Modal app-scoped live allocation key.
</ParamField>

<ParamField path="config" type="ComputerConfig | None">
  Desktop configuration used for both creation and config-hash compatibility validation.
</ParamField>

```python
import asyncio
from modal_computer_use import AsyncComputerSandbox, ComputerConfig

async def main() -> None:
    async with AsyncComputerSandbox.attach_or_create(
        name="my-desktop",
        config=ComputerConfig(),
    ) as computer:
        screenshot = await computer.screenshots.full()
        screenshot.save("output.png")

asyncio.run(main())
```

## Instance Methods

### `await computer.detach()`

Transfers lifecycle ownership to your code, releases the local Modal sandbox handle, and closes the HTTP and WebSocket connections. Prevents the context manager from terminating the sandbox on exit.

```python
async with AsyncComputerSandbox.create(config=ComputerConfig()) as computer:
    handle = computer.session_handle()
    await computer.detach()
# No termination on exit — you own the sandbox now.
```

---

### `await computer.terminate(wait=False)`

Terminates the Modal sandbox backing this instance. Pass `wait=True` to await full termination.

```python
await computer.terminate(wait=True)
```

<ParamField path="wait" type="bool" default="False">
  Block until the sandbox is fully stopped.
</ParamField>

---

### `computer.metadata()`

Returns the `SandboxRef` object with Modal metadata (sandbox ID, app name, name, run ID, owner, created-at, config hash, and tags).

```python
meta = computer.metadata()
print(meta.sandbox_id, meta.run_id)
```

---

### `computer.session_handle()`

Returns a frozen `ComputerSessionHandle` for passing to a deployed Modal Function. The handle encodes routing identity used by `borrow_async()` for a session handoff.

```python
handle = computer.session_handle()
# Pass to a Modal Function for borrow_async() usage.
```

---

## `ComputerSessionHandle` and `borrow_async()`

`ComputerSessionHandle` is a frozen, versioned object encoding the routing identity for one SDK-owned Modal desktop. You obtain it by calling `computer.session_handle()` on either a `ComputerSandbox` or `AsyncComputerSandbox` instance that was created (not just attached) with an explicit `modal_region`, `modal_environment`, and `vnc_mode` of `"off"` or `"view_only"`.

Inside a deployed Modal Function, use `borrow_async()` to connect to that desktop for one exclusive trajectory:

```python
FUNCTION_REGION = "us-west"

async def trajectory(
    handle: ComputerSessionHandle,
    task: str,
    run_id: str,
) -> None:
    async with handle.borrow_async(
        run_id=run_id,
        function_region=FUNCTION_REGION,
    ) as computer:
        for _ in range(3):
            screenshot = await computer.screenshots.full()
            action = await your_model_call(task, screenshot)
            await computer.actions.run([action])
```

<Note>
  For full details on session handoff semantics, lease validation, heartbeat behavior, and operation sequencing, see the session handoff guide.
</Note>

## Context Manager Ownership Rules

<Tabs>
  <Tab title="create() — owns the sandbox">
    ```python
    async with AsyncComputerSandbox.create(config=ComputerConfig()) as computer:
        await computer.mouse.click(320, 240)
    # On exit: terminate() → detach() → client.aclose()
    ```
    The SDK terminates the Modal sandbox, detaches the handle, and closes all connections.
  </Tab>
  <Tab title="attach() — does not own">
    ```python
    async with AsyncComputerSandbox.attach(sandbox_id="sb-abc123") as computer:
        await computer.mouse.click(320, 240)
    # On exit: detach() → client.aclose() — sandbox keeps running
    ```
    Exiting only releases the local handle and connections.
  </Tab>
  <Tab title="explicit detach() — transfers ownership">
    ```python
    async with AsyncComputerSandbox.create(config=ComputerConfig()) as computer:
        handle = computer.session_handle()
        await computer.detach()  # Prevents context exit from terminating.
    # On exit: no-op
    ```
    After `detach()`, you are responsible for calling `terminate()` when done.
  </Tab>
</Tabs>
