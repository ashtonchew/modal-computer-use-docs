## Computer Step

The 8 August 2026 promotion run compared two ways to execute one ordered action batch and capture its immediate screenshot within the same topology.

| Same-topology arm | p50 | p95 |
| --- | ---: | ---: |
| `actions.run()` then `screenshots.full()` | 47.14 ms | 58.22 ms |
| `computer.step()` | 44.29 ms | 52.57 ms |

The run retained 100 interleaved pairs per arm. It recorded zero failures, retries, replacements, and cleanup survivors.

Evidence: [Computer Step report](https://github.com/ashtonchew/modal-computer-use/blob/f6b9adeee54f584c345c813750758b7c7b5db744/docs/benchmark-results-2026-08-08-computer-step.md)

An immediate frame completes this timer. First visual change and application readiness use separate signals.

## Raw binary screenshot default

The optimized-default gate measured a full semantic screenshot followed by one pointer move.

| Same-topology arm | p50 | p95 |
| --- | ---: | ---: |
| Retained JSON/base64 screenshot path | 147.27 ms | 763.47 ms |
| Raw binary screenshot with `Screenshot` reconstruction | 81.11 ms | 739.17 ms |

Both arms retained 30 interleaved samples.

Evidence: [Optimized-default report](https://github.com/ashtonchew/modal-computer-use/blob/31bcafefbba2ba75653075a04b12ce2eb816c838/docs/benchmark-results-2026-08-08-optimized-default.md)

This timer used two SDK operations. The Computer Step section covers the fused route.

## Input-work capacity

The minimum tested runtime ran three independent mixed XTest capacity gates.

| Run | Weighted tokens per second | Batch p95 | RSS growth |
| --- | ---: | ---: | ---: |
| 1 | 527.40 | 131.89 ms | 0 B |
| 2 | 505.14 | 148.10 ms | 3,817,472 B |
| 3 | 380.70 | 206.17 ms | 29,941,760 B |

Each run completed 80 batches of 48 ordered actions. The product default is a 100-token refill with a 400-token burst.

Evidence: [Input-capacity report](https://github.com/ashtonchew/modal-computer-use/blob/1b60dc92e6998598a6db304a4a49de8fd3754b15/docs/benchmark-results-2026-08-08-input-capacity.md)

## Managed Image lifecycle

The managed standard Image completed 60 of 60 measured lifecycles with successful cleanup.

| Metric | Inline recipe | Managed exact ID | Change |
| --- | ---: | ---: | ---: |
| p50 | 15.47 s | 14.08 s | -8.95 percent |
| p95 | 44.68 s | 43.27 s | -3.15 percent |

The paired mean confidence interval crossed zero because both arms had large tail outliers. The result supports an opt-in managed standard Image. A universal default requires separate availability, rollback, and variant evidence.

Evidence: [Image lifecycle report](https://github.com/ashtonchew/modal-computer-use/blob/1b60dc92e6998598a6db304a4a49de8fd3754b15/docs/benchmark-results-2026-08-08-image-lifecycle.md)

## Complete action-to-frame paths

On 11 August 2026, the benchmark measured one left click at `(512, 384)` followed by the next validated full screenshot through four public SDK paths. It ran two warmups and 100 measured samples for each path. The timer started immediately before ordered action dispatch and ended after the next full screenshot was decoded and validated.

<div className="action-frame-results">

  | Path | p50 (ms) | p95 (ms) |
  | --- | ---: | ---: |
  | Modal Computer Use / `computer.step()` | 43.13 | 46.35 |
  | Daytona | 1039.59 | 1143.06 |
  | E2B | 15659.63 | 15744.76 |
  | Tzafon | 264.37 | 346.10 |

</div>

The run recorded zero failures, zero harness retries, zero replacement samples, and zero cleanup survivors.

These values describe complete paths under their recorded configurations. Use a matched-configuration campaign to compare provider implementations. Match caller placement, region, resources, screenshot format, and request shape.

Evidence: [dated report](https://github.com/ashtonchew/modal-computer-use/blob/46065138902e17d2525b8a76573c4d3811064462/docs/benchmark-results-2026-08-11-provider-action-frame.md) and [sanitized artifact](https://github.com/ashtonchew/modal-computer-use/blob/46065138902e17d2525b8a76573c4d3811064462/benchmark-data/external-provider-action-frame-2026-08-11.json)
