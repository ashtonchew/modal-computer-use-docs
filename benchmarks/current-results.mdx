## Computer Step

The 8 August 2026 promotion run measured one ordered action batch and its immediate screenshot as one fused HTTP operation.

| Same-topology arm | p50 | p95 |
| --- | ---: | ---: |
| `actions.run()` then `screenshots.full()` | 47.14 ms | 58.22 ms |
| `computer.step()` | **44.29 ms** | **52.57 ms** |

The run retained 100 interleaved pairs per arm. It recorded zero failures, retries, replacements, and cleanup survivors. The source was [`f6b9adeee54f584c345c813750758b7c7b5db744`](https://github.com/ashtonchew/modal-computer-use/blob/f6b9adeee54f584c345c813750758b7c7b5db744/docs/benchmark-results-2026-08-08-computer-step.md).

The Step frame is immediate. Changed pixels and application readiness use separate timers.

## Raw binary screenshot default

The optimized-default gate measured a full semantic screenshot followed by one pointer move.

| Same-topology arm | p50 | p95 |
| --- | ---: | ---: |
| Retained JSON/base64 screenshot path | 147.27 ms | 763.47 ms |
| Raw binary screenshot with `Screenshot` reconstruction | **81.11 ms** | **739.17 ms** |

Both arms retained 30 interleaved samples. The source was [`31bcafefbba2ba75653075a04b12ce2eb816c838`](https://github.com/ashtonchew/modal-computer-use/blob/31bcafefbba2ba75653075a04b12ce2eb816c838/docs/benchmark-results-2026-08-08-optimized-default.md).

This timer used two SDK operations. The Computer Step table above contains the fused measurement.

## Input-work capacity

The minimum tested runtime ran three independent mixed XTest capacity gates.

| Run | Weighted tokens per second | Batch p95 | RSS growth |
| --- | ---: | ---: | ---: |
| 1 | 527.40 | 131.89 ms | 0 B |
| 2 | 505.14 | 148.10 ms | 3,817,472 B |
| 3 | 380.70 | 206.17 ms | 29,941,760 B |

Each run completed 80 batches of 48 ordered actions. The product default is a 100-token refill with a 400-token burst. The [input-capacity report](https://github.com/ashtonchew/modal-computer-use/blob/1b60dc92e6998598a6db304a4a49de8fd3754b15/docs/benchmark-results-2026-08-08-input-capacity.md) explains the two-times safety margin and weighted costs.

## Managed Image lifecycle

The managed standard Image completed 60 of 60 measured lifecycles with successful cleanup.

| Metric | Inline recipe | Managed exact ID | Change |
| --- | ---: | ---: | ---: |
| p50 | 15.47 s | 14.08 s | -8.95 percent |
| p95 | 44.68 s | 43.27 s | -3.15 percent |

The paired mean confidence interval crossed zero because both arms had large tail outliers. The
result supports an opt-in managed standard Image. A universal default needs separate availability,
rollback, and variant evidence. See the [image lifecycle report](https://github.com/ashtonchew/modal-computer-use/blob/1b60dc92e6998598a6db304a4a49de8fd3754b15/docs/benchmark-results-2026-08-08-image-lifecycle.md).

## Historical 47.10 ms figure

The article combined separate medians:

- Raw screenshot: 37.25 ms
- Click: 9.85 ms
- Arithmetic sum: 47.10 ms

No fused request produced that historical value. The later Computer Step experiment measured a fused action-to-immediate-frame p50 of 44.29 ms. Keep the dates and scopes with both figures.
