`AnthropicAdapter` converts Anthropic Messages API `computer` tool actions into native `modal-computer-use` desktop operations. You provide a `ComputerSandbox` and a tool version; the adapter handles normalization, coordinate translation, policy checks, and dispatch. The adapter never calls the Anthropic API — your application code owns the model loop, API credentials, message history, and turn limits.

## Installation

```bash
uv add "modal-computer-use[modal,anthropic]"
```

Set `ANTHROPIC_API_KEY` in your environment before running any loop. Set `ANTHROPIC_MODEL` only when you need to override the default model.

## Tool versions

Anthropic's computer tool has three supported versions. Each version gates a specific set of actions:

<Tabs>
  <Tab title="computer_20251124 (recommended)">
    Use `computer_20251124` with beta header `computer-use-2025-11-24` for all new code. This is the default tool version used by `AnthropicAdapter`.

    ```python
    response = client.beta.messages.create(
        model="claude-sonnet-5",
        betas=["computer-use-2025-11-24"],
        tools=[{
            "type": "computer_20251124",
            "name": "computer",
            "display_width_px": 1280,
            "display_height_px": 800,
            "enable_zoom": True,
        }],
        messages=messages,
        max_tokens=4096,
    )
    ```

    **Adds:** `zoom` (when `enable_zoom=True`)
  </Tab>
  <Tab title="computer_20250124">
    Use `computer_20250124` with beta header `computer-use-2025-01-24` for compatible older models.

    ```python
    response = client.beta.messages.create(
        model="claude-sonnet-4-5",
        betas=["computer-use-2025-01-24"],
        tools=[{
            "type": "computer_20250124",
            "name": "computer",
            "display_width_px": 1280,
            "display_height_px": 800,
        }],
        messages=messages,
        max_tokens=4096,
    )
    ```

    **Adds over `computer_20241022`:** `scroll`, `left_mouse_down`, `left_mouse_up`, `hold_key`, `wait`, `triple_click`
  </Tab>
  <Tab title="computer_20241022 (legacy)">
    `computer_20241022` is accepted by the adapter for legacy integrations only. Do not use it in new API requests.

    It supports only the base action set: `mouse_move`, click variants, destination-only drag, `key`, `type`, `screenshot`, and `cursor_position`.
  </Tab>
</Tabs>

`AnthropicAdapter` uses `computer_20251124` by default. Zoom is off by default — set `enable_zoom=True` to enable it. The adapter rejects actions that the selected tool version does not support, so older versions fail closed rather than silently accepting newer action types.

## Supported actions

<Tabs>
  <Tab title="Base (all versions)">
    | Action | Description |
    |---|---|
    | `mouse_move` | Move the cursor to `coordinate` |
    | `left_click` | Left-click, optionally at `coordinate` with `key` modifier |
    | `right_click` | Right-click, optionally at `coordinate` with `key` modifier |
    | `middle_click` | Middle-click, optionally at `coordinate` with `key` modifier |
    | `double_click` | Double-click, optionally at `coordinate` with `key` modifier |
    | `left_click_drag` | Drag from `start_coordinate` to `coordinate` |
    | `key` | Press a key or chord (e.g., `"ctrl+c"`) |
    | `type` | Type a string of text |
    | `screenshot` | Capture the current screen |
    | `cursor_position` | Return the current cursor coordinates |

    A click without coordinates uses the current cursor position. A drag without `start_coordinate` uses the current cursor position as its start.
  </Tab>
  <Tab title="Enhanced (20250124+)">
    In addition to the base set, `computer_20250124` and `computer_20251124` support:

    | Action | Description |
    |---|---|
    | `triple_click` | Triple-click at `coordinate` with optional `key` modifier |
    | `left_mouse_down` | Press and hold the left mouse button |
    | `left_mouse_up` | Release the left mouse button |
    | `scroll` | Scroll in `scroll_direction` by `scroll_amount` clicks |
    | `hold_key` | Hold `text` key for `duration` seconds, with optional nested `actions` |
    | `wait` | Wait for `duration` seconds |

    **Field notes:**
    - `scroll_direction`: `"up"`, `"down"`, `"left"`, or `"right"`
    - `scroll_amount`: number of scroll clicks (integer ≥ 1)
    - `duration`: seconds (number); the adapter converts this to milliseconds for the daemon
    - `text` on `hold_key` gives the key name; `text` can also give a scroll modifier
    - `key` gives an optional click modifier
  </Tab>
  <Tab title="Zoom (20251124 only)">
    `computer_20251124` with `enable_zoom=True` adds:

    | Action | Description |
    |---|---|
    | `zoom` | Zoom into a rectangular `region` given as `[x0, y0, x1, y1]` |

    The adapter converts a zoom region to a full-resolution native region. Object-shaped regions (`{x0, y0, x1, y1}`) are also accepted for compatibility.
  </Tab>
</Tabs>

## Constructing the adapter

```python
from modal_computer_use.adapters.anthropic import AnthropicAdapter

adapter = AnthropicAdapter(
    computer,
    tool_version="computer_20251124",
    enable_zoom=True,
)
```

Apply a single action directly:

```python
adapter.apply({"action": "mouse_move", "coordinate": [500, 300]})
adapter.apply({"action": "left_click"})
```

## Building tool results

Use `anthropic_tool_result()` to build the Anthropic `tool_result` content block from a native `Screenshot` or `ActionResult`:

```python
from modal_computer_use.adapters.anthropic import anthropic_tool_result

# From a screenshot
screenshot = computer.screenshots.full()
tool_result = anthropic_tool_result(
    tool_use_id="toolu_abc123",
    result=screenshot,
)

# From an ActionResult (e.g., for errors or cursor_position)
from modal_computer_use.models import ActionResult

tool_result = anthropic_tool_result(
    tool_use_id="toolu_abc123",
    result=ActionResult(ok=False, message="computer action failed"),
)
```

For safe screenshot tracing metadata (dimensions, format, SHA-256, artifact URI, capture time, coordinate space — no image bytes):

```python
from modal_computer_use.adapters.anthropic import anthropic_screenshot_metadata

metadata = anthropic_screenshot_metadata(screenshot)
```

## The agent loop

The canonical loop keeps Anthropic's **provider-owned hosted `computer` tool** for exploratory navigation, sensitive steps, and actions whose next step depends on the intermediate screen. It optionally declares an **application-owned `computer_batch` tool** for predictable sequences that do not need intermediate visual replanning.

<Steps>
  <Step title="Declare the tools">
    Include the hosted `computer` tool in your tools list. Do not declare an input schema for it — Anthropic owns that schema and the computer-use classifier behavior.

    ```python
    tools = [
        {
            "type": "computer_20251124",
            "name": "computer",
            "display_width_px": display_width_px,
            "display_height_px": display_height_px,
            "enable_zoom": True,
        },
    ]
    ```
  </Step>

  <Step title="Send the task and get a response">
    Always pass `betas=[version.beta_header]` matching your tool version. Keep the complete assistant content in message history.

    ```python
    response = client.beta.messages.create(
        model="claude-sonnet-5",
        betas=["computer-use-2025-11-24"],
        max_tokens=4096,
        tools=tools,
        messages=messages,
    )
    messages.append({"role": "assistant", "content": response.content})
    ```
  </Step>

  <Step title="Check stop_reason">
    Continue the tool loop only when `stop_reason == "tool_use"`. When it is anything else, the model has finished — return the response.

    ```python
    if response.stop_reason != "tool_use":
        return response
    ```
  </Step>

  <Step title="Execute each tool_use block">
    Collect all `tool_use` blocks from `response.content`. Execute them sequentially (for the shared screen). For each block, dispatch with the adapter and build a `tool_result`:

    ```python
    tool_results = []
    for tool_use in tool_uses:
        action = dict(tool_use.input)
        action_result = adapter.apply(action)
        tool_result = _build_tool_result(computer, tool_use.id, action, action_result)
        tool_results.append(tool_result)
    ```
  </Step>

  <Step title="Return all tool results in one user message">
    Add one matching `tool_result` for every `tool_use`, including failures. Put all results together in the next user message.

    ```python
    messages.append({"role": "user", "content": tool_results})
    ```
  </Step>

  <Step title="Stop when the turn budget is exhausted">
    If the final allowed response requests a tool, stop before executing it — the loop cannot return the required tool result within its turn budget. Always set independent limits for turns, trajectory actions, recursive batch actions, per-action time, and total elapsed time.
  </Step>
</Steps>

## Using computer_batch for predictable sequences

The `computer_batch` custom tool lets the model request a sequence of actions that execute as a single ordered daemon batch, stopping on the first error. Use it for sequences where no action needs an intermediate screen observation.

```python
batch_result = adapter.apply_many(
    [
        {"action": "left_click", "coordinate": [420, 280]},
        {"action": "type", "text": "Example"},
        {"action": "key", "text": "Tab"},
    ],
    continue_on_error=False,
    screenshot_after=True,
)
```

<Warning>
All batch coordinates refer to the screenshot observed **before** the batch. The model cannot inspect an intermediate screen and replan inside a single `computer_batch` call. Keep the hosted `computer` tool for exploration, sensitive steps, recovery, and any action whose successor depends on an intermediate screen.
</Warning>

## Complete minimal loop example

The following is a condensed version of the canonical loop from [`examples/anthropic_message_server.py`](https://github.com/ashtonchew/modal-computer-use/blob/main/examples/anthropic_message_server.py):

```python
import os
from time import monotonic
from modal_computer_use import BrowserConfig, ComputerConfig, ComputerSandbox, ResourceConfig
from modal_computer_use.adapters.anthropic import AnthropicAdapter, anthropic_tool_result
from modal_computer_use.models import ActionResult, Screenshot

DEFAULT_MODEL = "claude-sonnet-5"
MAX_TURNS = 40
MAX_ELAPSED_SECONDS = 300.0


def run_anthropic_computer_loop(
    *, client, computer, task, display_width_px, display_height_px, model=DEFAULT_MODEL
):
    adapter = AnthropicAdapter(computer, tool_version="computer_20251124", enable_zoom=True)
    tools = [
        {
            "type": "computer_20251124",
            "name": "computer",
            "display_width_px": display_width_px,
            "display_height_px": display_height_px,
            "enable_zoom": True,
        }
    ]
    messages = [{"role": "user", "content": task}]
    started_at = monotonic()

    for turn in range(MAX_TURNS):
        if monotonic() - started_at > MAX_ELAPSED_SECONDS:
            raise RuntimeError("loop exceeded time budget")

        response = client.beta.messages.create(
            model=model,
            max_tokens=4096,
            betas=["computer-use-2025-11-24"],
            tools=tools,
            messages=messages,
        )
        messages.append({"role": "assistant", "content": response.content})

        # Stop when Claude is done
        if response.stop_reason != "tool_use":
            return response

        if turn == MAX_TURNS - 1:
            raise RuntimeError(f"loop exceeded {MAX_TURNS} turns")

        tool_uses = [
            block for block in response.content
            if getattr(block, "type", None) == "tool_use"
        ]

        tool_results = []
        for tool_use in tool_uses:
            try:
                action = dict(tool_use.input)
                action_result = adapter.apply(action)

                if not action_result.ok:
                    result = anthropic_tool_result(
                        tool_use_id=tool_use.id,
                        result=ActionResult(ok=False, message="computer action failed"),
                    )
                elif action.get("action") == "cursor_position":
                    x, y = int(action_result.output["x"]), int(action_result.output["y"])
                    result = anthropic_tool_result(
                        tool_use_id=tool_use.id,
                        result=ActionResult(ok=True, message=f"X={x},Y={y}"),
                    )
                elif action.get("action") in {"screenshot", "zoom"}:
                    screenshot = Screenshot.model_validate(action_result.output)
                    result = anthropic_tool_result(tool_use_id=tool_use.id, result=screenshot)
                else:
                    screenshot = computer.screenshots.full()
                    result = anthropic_tool_result(tool_use_id=tool_use.id, result=screenshot)
            except Exception as exc:
                result = anthropic_tool_result(
                    tool_use_id=tool_use.id,
                    result=ActionResult(ok=False, message=f"computer tool failed: {type(exc).__name__}"),
                )
            tool_results.append(result)

        messages.append({"role": "user", "content": tool_results})

    raise RuntimeError(f"loop exceeded {MAX_TURNS} turns")


def main():
    from anthropic import Anthropic

    width, height = 1280, 800
    config = ComputerConfig(
        desktop={"resolution": (width, height)},
        resources=ResourceConfig(profile="browser"),
        browser=BrowserConfig(kind="chromium", prewarm=True),
    )
    with ComputerSandbox.create(config=config, wait=True) as computer:
        computer.ensure_browser_ready(config)
        response = run_anthropic_computer_loop(
            client=Anthropic(),
            computer=computer,
            model=os.environ.get("ANTHROPIC_MODEL", DEFAULT_MODEL),
            display_width_px=width,
            display_height_px=height,
            task=(
                "Open https://example.com in the browser. Verify that the page title is "
                "'Example Domain', then report the title and stop. Do not sign in, "
                "submit forms, or change data."
            ),
        )
        print(response.content)


if __name__ == "__main__":
    main()
```

<Tip>
The production loop in the examples directory adds the `computer_batch` custom tool, per-action timeouts, trajectory action limits, and native screenshot/zoom output reuse. Start with the full example when building production loops.
</Tip>

## Enabling zoom

Set `enable_zoom=True` on both the adapter and the hosted tool declaration:

```python
adapter = AnthropicAdapter(
    computer,
    tool_version="computer_20251124",
    enable_zoom=True,
)

hosted_tool = {
    "type": "computer_20251124",
    "name": "computer",
    "display_width_px": 1280,
    "display_height_px": 800,
    "enable_zoom": True,
}
```

Zoom is only available with `computer_20251124`. The adapter ignores `enable_zoom=True` on older versions.

## Coordinate spaces

If you resize screenshots before sending them to the model, supply a `CoordinateSpace` so the adapter can translate model coordinates to desktop coordinates:

```python
from modal_computer_use import CoordinateSpace
from modal_computer_use.adapters.anthropic import AnthropicAdapter

space = CoordinateSpace(
    desktop_width=1440,
    desktop_height=900,
    image_width=720,
    image_height=450,
)
adapter = AnthropicAdapter(
    computer,
    tool_version="computer_20251124",
    enable_zoom=True,
    coordinate_space=space,
)
```

See [Adapter Overview — Coordinate spaces](/adapters/overview#coordinate-spaces) for the full explanation.

## Policy hooks

Pass `before_action` to intercept every normalized action before execution:

```python
from modal_computer_use.models import ActionDecision

def my_policy(action, context):
    if action.type == "type":
        return ActionDecision(decision="ask_user", reason="typing requires confirmation")
    return ActionDecision(decision="allow")

adapter = AnthropicAdapter(
    computer,
    tool_version="computer_20251124",
    before_action=my_policy,
)
```

See [Adapter Overview — Policy hooks](/adapters/overview#policy-hooks) for details on `ActionDecision` values.

## Safety guidelines

<Warning>
Run the desktop in a dedicated virtual machine or container with minimum privileges. Treat page content and screenshots as untrusted input. Anthropic's prompt-injection detection for the hosted computer tool does not replace isolation, allowlists, validation, or confirmation.
</Warning>

- Allow only the required network destinations.
- Ask for confirmation before any action that has a meaningful external result or requires consent.
- Do not give the environment sensitive data unless the task explicitly requires it.
- Record action paths for review, and remove secrets and provider payloads from records.
- Anthropic's injection detection does not automatically extend to `computer_batch`. Validate `computer_batch` inputs independently.
- Always set turn, action, and time limits.
